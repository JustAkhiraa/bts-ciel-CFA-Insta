Coffre-fort connecté

Le projet entier, sur une page, pour le coffre fixe et la mallette. Le cours · Les exercices

⚡ Le principe

badge → lecteur RFID → ESP32
→ servo (verrou) + capteurs
→ Wi-Fi → serveur → base
→ supervision, alertes

Le badge RFID

13,56 MHz, sans pile :
alimenté par le champ du lecteur. Il donne son UID.

Lecteur MFRC522 : bus SPI, 3,3 V.

L'UID se lit et se copie : ce n'est pas un secret.

API ou cache

API :
toujours à jour, mais rien sans réseau.

Cache :
marche sans réseau, mais un badge retiré marche encore.

Les deux :
l'API d'abord, le cache en secours.

Le servomoteur

PWM 50 Hz → une impulsion / 20 ms
durée ≈ 1 à 2 ms → l'angle

Alimentation à part, masse commune.

L'effraction

Contact magnétique · vibration · anti-forçage.

Porte ouverte sans badge accepté = intrusion.

Trois événements :
autorisé, refusé, intrusion.

⚡ Le réseau IoT

WPA2 · adresse fixe ou réservation DHCP · VLAN IoT · pare-feu · peu de ports ouverts.

Le coffre ne parle qu'au serveur, sur un seul port.

⚡ HTTP ou MQTT

HTTP :
le coffre demande, le serveur répond (80, 443).

MQTT :
publier et s'abonner, via un broker (1883, 8883). Le serveur peut envoyer un ordre.

LWT :
le broker annonce « hors ligne » si le coffre disparaît.

La base

utilisateur · badge (actif) · evenement

Requêtes préparées contre l'injection SQL.

Sauvegardes par cron :
minute, heure, jour, mois, jour de semaine.

La sécurité

Jeton d'API · HTTPS si possible · journal de tous les accès · anti-rejeu · cloisonnement.

Tests :
scan de ports, injection SQL, ouverture forcée.

La mallette

Batterie et veille · file d'événements hors réseau · alerte de déplacement · l'heure de l'événement, pas celle de l'envoi (NTP).
