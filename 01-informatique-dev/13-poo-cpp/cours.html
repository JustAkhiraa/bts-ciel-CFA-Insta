POO en C++

Jusqu'ici, un programme était une suite d'instructions qui manipulent des données. La programmation orientée objet range ensemble les données et ce qu'on en fait, dans des objets. Le chapitre pose les idées, objet, classe, attribut, méthode, et les quatre principes, puis les bases du C++, le langage dans lequel on les pratiquera :
afficher, lire, et manipuler des chaînes. Viennent ensuite les classes et les objets en C++, puis l'encapsulation :
des attributs protégés, qu'on ne lit et ne modifie que par des méthodes capables de refuser une valeur incohérente. La dernière partie suit la vie d'un objet :
le constructeur qui le prépare, le destructeur qui libère ce qu'il a pris, et la mémoire réservée avec new.

📌

Résumé flash

Un objet a des attributs (ce qu'il est) et des méthodes (ce qu'il fait). La classe est le modèle, l'objet un exemplaire fabriqué d'après lui. Quatre principes :
encapsulation, abstraction, héritage, polymorphisme.

En C++ :
#include <iostream>, using namespace std;, puis cout << pour afficher et cin >> pour lire, sans code de format ni &.

string remplace le tableau de char, getline lit une ligne entière, et après un cin >>, il faut un cin.ignore().

Encapsulation :
attributs private, méthodes public. On lit par un getter, on modifie par un setter, qui peut refuser une valeur.

Constructeur :
même nom que la classe, aucun type de retour, appelé à la création. Destructeur :
~ devant le nom, appelé à la fin de la vie de l'objet. Un attribut pointeur demande un new[] dans le constructeur, un delete[] dans le destructeur, et une copie profonde.

01Qu'est-ce qu'un objet ?

La programmation orientée objet, la POO, est une manière de concevoir un programme en l'organisant autour d'objets. Un objet représente un élément, concret ou abstrait, du système qu'on veut programmer :

DomaineDes objets
Informatiqueordinateur, serveur, capteur
Réseaurouteur, commutateur, pare-feu
Gestionutilisateur, compte, produit

Chaque objet possède deux choses :
des informations qui le décrivent et des actions qu'il sait faire. Les premières s'appellent des attributs, les secondes des méthodes.

🧠 Un nom et des verbes

Pour trouver les attributs et les méthodes d'un objet, on le décrit en français. Les noms et adjectifs (« sa marque », « sa mémoire », « allumé ») sont ses attributs ; les verbes (« démarrer », « afficher ») sont ses méthodes.

02Procédural ou objet : deux façons d'organiser

Il y a plusieurs façons d'organiser un programme. Celle que vous connaissez déjà, c'est la programmation procédurale :
le programme est une suite de fonctions et d'instructions qui manipulent des données. C'est celle du langage C.

C
#include <stdio.h>

int main()
{
    int temperature = 25;
    printf("Temperature : %d degres\n", temperature);
    return 0;
}
sortie réelle
Temperature : 25 degres

temperature est une variable qui contient une donnée ; printf() est une fonction qui l'affiche. La donnée et ce qu'on en fait sont séparés.

En programmation orientée objet, on les regroupe. En C++, l'outil pour cela est la classe :
elle réunit les données et les opérations qui leur sont associées.

C++
#include <iostream>
using namespace std;

class Capteur {
public:
    int temperature;

    void afficher() {
        cout << "Temperature : "
             << temperature << " degres" << endl;
    }
};

int main()
{
    Capteur c;
    c.temperature = 25;
    c.afficher();
    return 0;
}
sortie réelle
Temperature : 25 degres
Quatre mots, et ce qu'ils désignent dans ce programme
MotIciC'est…
classeCapteurle modèle : ce que tout capteur possède et sait faire
attributtemperatureune donnée rangée dans l'objet
méthodeafficher()une fonction qui appartient à la classe
objetcun capteur précis, fabriqué d'après le modèle
💡 Vous avez déjà vu la moitié de l'idée : la struct

Une struct du C regroupait déjà des données de types différents (chapitre 12, section 27). La classe va plus loin :
elle range aussi les fonctions avec les données.

La méthode afficher() lit temperature directement, sans qu'on la lui passe en paramètre, parce qu'elles sont dans le même objet.

Et le point de c.temperature est celui de la structure : « le champ temperature de c ».

⚠️ Le point-virgule après l'accolade de la classe

Comme pour une struct, la définition d'une classe se termine par };. L'oublier provoque une erreur de compilation souvent signalée… à la ligne suivante.

03Ce que la POO apporte

AvantageCe que cela veut dire
Organisationle programme est structuré en classes et en objets
Réutilisationune classe sert dans plusieurs parties d'un programme, ou dans un autre
Maintenancele code est plus facile à comprendre et à modifier : s'il est bien conçu
Évolutivitéajouter une fonctionnalité est plus simple quand l'organisation s'y prête
Modélisationle programme représente directement les éléments du système : un routeur, un capteur, un compte

« S'il est bien conçu » n'est pas une précaution de style :
une mauvaise découpe en classes rend un programme plus difficile à lire qu'une bonne découpe en fonctions. La POO est un outil, pas une garantie.

04Les quatre principes fondamentaux

Quatre idées font la POO. Elles seront étudiées une par une dans les chapitres suivants ; il suffit pour l'instant de savoir les nommer et de reconnaître un exemple.

L'encapsulation est la première étudiée : sections 17 à 25.

Encapsulation :
le mot de passe d'administration est dans la box, et on ne peut le changer que par son interface.

Abstraction :
on la branche et elle marche, sans savoir comment elle négocie avec l'opérateur. Héritage :
une « box fibre » est une box, avec en plus un module optique.

Polymorphisme :
« redémarrer » marche sur toutes les box, mais chaque modèle le fait à sa façon.

💡 Les mêmes idées, déjà vues en Python

Classes, encapsulation, héritage et polymorphisme ont été travaillés en Python (chapitre 8). Les principes sont les mêmes ; ce qui change en C++, c'est l'écriture :
les types déclarés, public:, le point-virgule.

05Les bibliothèques : #include

Une bibliothèque est un ensemble de fonctionnalités déjà écrites et mises à disposition des programmeurs :
des fonctions, des classes, des types de données, des constantes, des outils.

On réutilise ce code au lieu de tout programmer à partir de zéro.

🛠️ La syntaxe
C++
#include <nom_bibliotheque>

#include <iostream>       // entrées et sorties : cout, cin

Le préprocesseur traite cette directive avant la compilation :
il insère à sa place ce que la bibliothèque déclare. C'est le même mécanisme que #include <stdio.h> en C.

Les bibliothèques standard les plus utilisées
BibliothèqueRôleSon équivalent en C
<iostream>entrées et sorties standard<stdio.h>
<string>chaînes de caractères<string.h>
<cmath>fonctions mathématiques<math.h>
<iomanip>mise en forme de l'affichageles formats de printf
<fstream>lecture et écriture de fichiersfopen, fprintf…
<vector>tableaux dynamiquesmalloc et un tableau
<cstdlib>fonctions générales et conversions<stdlib.h>

Les bibliothèques du C++ s'écrivent sans .h. Et la troisième colonne n'est pas une curiosité :
un programme C++ peut encore utiliser printf, mais on ne mélange pas les deux styles dans un même affichage.

06L'espace de noms std

Un espace de noms (namespace) regroupe des éléments sous un même nom. Il sert à éviter les conflits :
deux bibliothèques peuvent chacune avoir une fonction afficher sans se gêner, si elles sont dans deux espaces différents.

La bibliothèque standard du C++ range tout dans un espace appelé std, notamment cout, cin, endl et string. Pour s'en servir, on précise l'espace devant chaque nom, avec l'opérateur :: :

C++
#include <iostream>

int main()
{
    std::cout << "Bonjour BTS CIEL" << std::endl;
    return 0;
}
sortie réelle
Bonjour BTS CIEL

std désigne l'espace de noms standard · :: est l'opérateur de résolution de portée · cout affiche · endl passe à la ligne.

Pour ne pas répéter std:: partout, on écrit une fois using namespace std; :

C++
#include <iostream>
using namespace std;

int main()
{
    cout << "Bonjour BTS CIEL" << endl;
    return 0;
}
sortie réelle
Bonjour BTS CIEL

Les deux écritures sont correctes et donnent exactement le même programme.

💡 Pourquoi les professionnels écrivent souvent std::

using namespace std; fait entrer tous les noms de la bibliothèque standard : il y en a des centaines. Dans un petit programme d'exercice, c'est pratique.

Dans un gros projet, cela peut créer exactement les conflits que l'espace de noms devait éviter. D'où les deux usages, qu'il faut savoir lire.

07Le squelette d'un programme C++

C++
#include <iostream>
#include <string>
using namespace std;

int main()
{
    // Déclaration des variables

    // Instructions du programme

    return 0;
}

Les bibliothèques d'abord, puis l'espace de noms, puis main. Le fichier s'enregistre avec l'extension .cpp, et non .c, que le compilateur traiterait comme du C.

💡 Ce qui ne change pas depuis le C

int main(), return 0;, les { }, le ; à la fin de chaque instruction, les types int, float, char, les if, for, while :
tout ce qui a été appris en C s'écrit de la même façon en C++. Ce qui change d'abord, c'est l'affichage et la saisie.

08Afficher : cout et <<

cout est le flux de sortie standard :
ce qu'on lui envoie apparaît à l'écran. On envoie avec <<, l'opérateur d'insertion.

🛠️ La syntaxe
C++
cout << expression;
C++
#include <iostream>
using namespace std;

int main()
{
    cout << "Bienvenue en C++";
    return 0;
}
sortie réelle
Bienvenue en C++

Pour afficher une variable, on l'insère à la suite, et on peut enchaîner autant de << qu'on veut :

C++
#include <iostream>
using namespace std;

int main()
{
    int age = 20;
    float moyenne = 15.5;

    cout << "Age : " << age << endl;
    cout << "Moyenne : " << moyenne << endl;
    return 0;
}
sortie réelle
Age : 20
Moyenne : 15.5
💡 Plus de code de format

printf demandait de dire le type : %d, %f. cout le devine d'après la variable. Contrepartie :
15.5 s'affiche 15.5, et non 15.50 comme avec %.2f.

Pour fixer le nombre de décimales, il faut <iomanip> :
cout << fixed << setprecision(2) << moyenne.

Passer à la ligne : endl ou \n

C++
cout << "Premiere ligne" << endl;
cout << "Deuxieme ligne" << endl;
sortie réelle
Premiere ligne
Deuxieme ligne
C++
cout << "Premiere ligne\n";
cout << "Deuxieme ligne\n";
sortie réelle
Premiere ligne
Deuxieme ligne

Les deux passent à la ligne. endl fait en plus vider immédiatement l'affichage ; pour un exercice, la différence ne se voit pas.

⚠️ cout n'ajoute aucun espace

cout << "Age :" << age affiche Age :20. Les espaces sont à mettre dans les guillemets : "Age : ".

09Lire : cin et >>

cin est le flux d'entrée standard :
il récupère ce qui est tapé au clavier. On le lit avec >>, l'opérateur d'extraction, qui range la valeur dans une variable.

🛠️ La syntaxe · les chevrons pointent vers la variable
C++
cin >> variable;
C++
#include <iostream>
using namespace std;

int main()
{
    int age;

    cout << "Saisir votre age : ";
    cin >> age;
    cout << "Votre age est : " << age << endl;
    return 0;
}
sortie réelle · saisies : 20
Saisir votre age : Votre age est : 20

Pas de & :
cin sait écrire dans la variable sans qu'on lui donne son adresse. C'est l'une des premières simplifications par rapport à scanf.

🔧 Corrigé · des guillemets droits, et la ligne affichée qui va avec

L'exemple du cours écrit cout << « votre age est " << age :
il ouvre la chaîne par un guillemet français «.

Le compilateur ne connaît que le guillemet droit " et refuse le programme. (C'est souvent un traitement de texte qui remplace les guillemets tout seul.)

C++ · ne compile pas
#include <iostream>
using namespace std;

int main()
{
    int age;
    cout << "Saisir votre age : ";
    cin >> age;
    cout << « votre age est " << age << endl;
    return 0;
}

L'exécution annoncée, Votre age est : 20, avec une majuscule et deux points, ne correspondait pas non plus au texte du programme. L'exemple corrigé ci-dessus écrit la chaîne qui donne cette ligne.

On peut lire plusieurs valeurs d'un coup, en enchaînant les >>. Elles se tapent séparées par une espace ou par Entrée :

C++
#include <iostream>
using namespace std;

int main()
{
    int a, b;

    cout << "Saisir deux entiers : ";
    cin >> a >> b;
    cout << "Somme : " << a + b << endl;
    return 0;
}
sortie réelle · saisies : 10 puis 5
Saisir deux entiers : Somme : 15

10Les chaînes : string et getline

Le C++ a un vrai type chaîne :
string, fourni par <string>. Plus de tableau de char à dimensionner, plus de '\0' à prévoir :
la chaîne prend la taille dont elle a besoin.

C++
#include <iostream>
#include <string>
using namespace std;

int main()
{
    string nom;

    cout << "Saisir votre nom : ";
    cin >> nom;
    cout << "Nom : " << nom << endl;
    return 0;
}
sortie réelle · saisies : BTS CIEL
Saisir votre nom : Nom : BTS

Tapé BTS CIEL, lu BTS :
comme scanf("%s"), cin >> s'arrête au premier espace. Pour lire une ligne entière, espaces compris, on utilise getline :

🛠️ La syntaxe
C++
getline(cin, variable);
C++
#include <iostream>
#include <string>
using namespace std;

int main()
{
    string nom;

    cout << "Saisir votre nom complet : ";
    getline(cin, nom);
    cout << "Nom complet : " << nom << endl;
    return 0;
}
sortie réelle · saisies : Jean Dupont
Saisir votre nom complet : Nom complet : Jean Dupont
Saisie : BTS CIEL
InstructionCe qu'elle faitValeur récupérée
cin >> nomlit une valeur, s'arrête au premier espace ou caractère blanc, laisse le retour à la ligne dans le fluxBTS
getline(cin, nom)lit la ligne complète, espaces compris, et s'arrête au \nBTS CIEL

C'est le même couple qu'en C :
scanf("%s") s'arrêtait à l'espace, fgets lisait la ligne entière (chapitre 12, section 34).

11Le piège : getline après cin

Ce programme semble juste. Il demande un âge, puis un nom complet :

C++
#include <iostream>
#include <string>
using namespace std;

int main()
{
    int age;
    string nom;

    cout << "Age : ";
    cin >> age;
    cout << "Nom complet : ";
    getline(cin, nom);
    cout << "[" << nom << "]" << endl;
    return 0;
}
sortie réelle · saisies : 20 puis Jean Dupont
Age : Nom complet : []

Le programme ne laisse pas le temps de taper le nom : nom reste vide. Que s'est-il passé ? L'utilisateur a tapé 20 puis Entrée.

La touche Entrée ajoute un caractère \n dans le flux d'entrée. cin >> age prend le 20… et laisse le \n.

La solution :
cin.ignore(); juste après le cin >>. Elle retire le caractère resté dans le flux.

C++
#include <iostream>
#include <string>
using namespace std;

int main()
{
    int age;
    string nom;

    cout << "Age : ";
    cin >> age;
    cin.ignore();                 // retire le \n laissé par la touche Entrée
    cout << "Nom complet : ";
    getline(cin, nom);
    cout << "[" << nom << "]" << endl;
    return 0;
}
sortie réelle · saisies : 20 puis Jean Dupont
Age : Nom complet : [Jean Dupont]
  1. cin >> age récupère l'âge ;
  2. cin.ignore() supprime le retour à la ligne ;
  3. getline() attend vraiment la saisie du nom complet.
💡 cin.ignore() n'enlève qu'UN caractère

Si l'utilisateur tape 20, puis une espace, puis Entrée, il reste deux caractères : l'espace et le \n. cin.ignore() retire l'espace, et getline retombe sur le \n : le nom est de nouveau vide. Vérifié au compilateur.

Deux écritures règlent aussi ce cas :
cin >> ws; (« saute tous les blancs ») ou cin.ignore(numeric_limits<streamsize>::max(), '\n'); (« jette tout jusqu'au retour à la ligne », avec <limits>). Pour les exercices du cours, cin.ignore() suffit.

La règle à retenir :
un getline qui suit un cin >> doit être précédé d'un cin.ignore(). Deux getline de suite, eux, n'en ont pas besoin.

12Classe, attributs, méthodes

Une classe est un modèle, un plan de fabrication. On ne déclare pas les variables de chaque ordinateur une par une :
on écrit une fois la classe Ordinateur, et on fabrique autant d'ordinateurs qu'on veut.

Un attribut est une variable déclarée dans la classe. Il décrit ce que l'objet est :

AttributTypeCe qu'il décrit
marquestringla marque
memoireRAMintla mémoire, en Go
prixfloatle prix

Une méthode est une fonction déclarée dans la classe. Elle décrit ce que l'objet fait :

MéthodeRôle
afficherInformations()afficher les caractéristiques
demarrer()démarrer l'ordinateur
arreter()arrêter l'ordinateur

Une classe donne plusieurs objets. Ils ont les mêmes attributs, mais chacun ses propres valeurs :

ObjetmarquememoireRAM
pc1Alpha16 Go
pc2Bravo8 Go
pc3Charlie32 Go
💡 Les quatre mots, en une ligne chacun

Classe : le modèle. Objet :
un exemplaire fabriqué d'après ce modèle (une instance).

Attributs : les caractéristiques. Méthodes : les comportements.

13Déclarer une classe

Le mot-clé class, le nom, puis le contenu entre accolades :

C++
class NomClasse
{
    // les attributs
    // les méthodes
};

Le point-virgule final est obligatoire. L'oublier donne expected ';' after class.

Les attributs se déclarent comme des variables ordinaires. Les méthodes, comme des fonctions, avec leur corps entre accolades :

C++
class Ordinateur
{
public:
    string marque;
    int memoireRAM;
    float prix;

    void afficherInformations()
    {
        cout << "Marque : " << marque << endl;
    }
};

Dans une méthode, marque désigne directement l'attribut de l'objet :
pas besoin de le passer en paramètre.

14Le piège : sans public:, tout est privé

Le cours montre d'abord une classe sans le mot public:. Elle compile, tant qu'on ne touche pas à ses attributs :

C++
class Ordinateur
{
    string marque;
    int memoireRAM;
};

Mais dès que main écrit pc1.marque = "Alpha";, le compilateur refuse :

erreur réelle du compilateur
'marque' is a private member of 'Ordinateur'

Dans une classe, tout est privé par défaut :
seul le code de la classe peut y toucher. public: ouvre l'accès à ce qui le suit.

⚠️ Une différence avec la struct

Dans une struct, tout est public par défaut. Dans une class, tout est privé. C'est la différence qui compte ici ; l'autre concerne l'héritage.

Le privé n'est pas une erreur :
c'est l'encapsulation (section 18) :
la classe protège ses données.

15Créer des objets et s'en servir

Créer un objet s'appelle l'instanciation. Un objet est une variable dont le type est une classe :

C++
Ordinateur pc1;
Ordinateur pc2;

On atteint un attribut, ou on appelle une méthode, avec l'opérateur point :

C++
pc1.marque = "Alpha";      // écrire un attribut
pc1.afficherInformations(); // appeler une méthode

Le programme complet du cours :
deux ordinateurs, leurs informations, puis leur affichage.

C++
#include <iostream>
#include <string>
using namespace std;

class Ordinateur
{
public:
    string marque;
    int memoireRAM;
    float prix;

    void afficherInformations()
    {
        cout << "Marque : " << marque << endl;
        cout << "Memoire RAM : " << memoireRAM << " Go" << endl;
        cout << "Prix : " << prix << " euros" << endl;
    }
};

int main()
{
    Ordinateur pc1;
    pc1.marque = "Alpha";
    pc1.memoireRAM = 16;
    pc1.prix = 850;

    Ordinateur pc2;
    pc2.marque = "Bravo";
    pc2.memoireRAM = 8;
    pc2.prix = 650;

    // Affichage des informations
    cout << "Ordinateur 1 :" << endl;
    pc1.afficherInformations();
    cout << endl;
    cout << "Ordinateur 2 :" << endl;
    pc2.afficherInformations();
    return 0;
}
sortie réelle
Ordinateur 1 :
Marque : Alpha
Memoire RAM : 16 Go
Prix : 850 euros

Ordinateur 2 :
Marque : Bravo
Memoire RAM : 8 Go
Prix : 650 euros

Modifier pc1 ne change rien à pc2 :
chaque objet a ses propres attributs.

16Définir une méthode hors de la classe : ::

On peut déclarer la méthode dans la classe, et écrire son contenu ailleurs. La classe reste courte et lisible.

Dans la classe, la déclaration seule, terminée par un point-virgule. Dehors, la définition, précédée du nom de la classe et de ::.

C++
#include <iostream>
#include <string>
using namespace std;

17Pourquoi l'encapsulation ?

Jusqu'ici, les attributs étaient déclarés public. Le programme principal main() pouvait donc les lire et les modifier directement.

C'est pratique, mais rien ne contrôle ce qu'on y écrit :

C++
#include <iostream>
#include <string>
using namespace std;

class Ordinateur
{
public:
    string marque;
    int memoireRAM;
};

int main()
{
    Ordinateur pc1;

    pc1.marque = "Alpha";
    pc1.memoireRAM = -50;

    cout << pc1.memoireRAM;

    return 0;
}
sortie réelle
-50

Le programme accepte -50 Go de mémoire vive. Il compile, il s'exécute, et il garde une valeur qui n'a aucun sens.

Le défaut n'est pas dans main() :
c'est la classe qui laisse faire. L'encapsulation lui donne le moyen de refuser.

18Définition de l'encapsulation

L'encapsulation est un principe fondamental de la programmation orientée objet, le premier des quatre (section 4).

Elle consiste à protéger les données d'un objet en limitant leur accès direct depuis l'extérieur de la classe. La lecture et la modification des attributs passent par des méthodes prévues pour ça, qui les contrôlent.

💡 Ses quatre objectifs
  • Protéger les attributs d'une classe.
  • Éviter les modifications incorrectes des données.
  • Contrôler l'accès aux informations d'un objet.
  • Garantir la cohérence des données.
🧠 Le guichet de la banque

On ne passe pas derrière le comptoir pour se servir dans le coffre. On s'adresse au guichet, qui vérifie la demande avant de toucher au coffre.

Le coffre, ce sont les attributs privés. Le guichet, ce sont les méthodes publiques.

19Les trois spécificateurs d'accès

En C++, trois mots-clés règlent qui a le droit d'utiliser un membre de la classe, attribut ou méthode :

  • private (privé) :
    accessible uniquement à l'intérieur de la classe.
  • public (public) :
    accessible aussi depuis l'extérieur de la classe.
  • protected (protégé) :
    accessible à l'intérieur de la classe et dans ses classes dérivées (l'héritage).

public : ouvert à tous

Le mot-clé public rend les membres accessibles depuis l'intérieur et depuis l'extérieur de la classe. Les attributs s'utilisent alors directement dans main(), et ce programme compile :

C++
#include <iostream>
#include <string>
using namespace std;

class Ordinateur
{
public:
    string marque;
    int memoireRAM;
};

int main()
{
    Ordinateur pc1;

    pc1.marque = "Alpha";
    pc1.memoireRAM = 16;

    return 0;
}

private : réservé à la classe

Le mot-clé private rend les membres accessibles uniquement depuis l'intérieur de la classe, et par les amis qu'elle autorise elle-même (le mot-clé friend, seulement cité ici).

Le même programme, avec private:, est refusé :

C++ · ne compile pas
#include <iostream>
#include <string>
using namespace std;

class Ordinateur
{
private:
    string marque;
    int memoireRAM;
};

int main()
{
    Ordinateur pc1;

    pc1.marque = "Alpha";   // Erreur
    pc1.memoireRAM = 16;    // Erreur

    return 0;
}
erreur réelle du compilateur
'marque' is a private member of 'Ordinateur'
'memoireRAM' is a private member of 'Ordinateur'

Une erreur par attribut. La faute est attrapée à la compilation :
un programme qui touche à un attribut privé ne peut même pas être lancé.

protected : la classe et ses filles

Le mot-clé protected rend les membres accessibles dans la classe et dans ses classes dérivées (les classes filles). Depuis l'extérieur, ils restent fermés.

C++
class Equipement
{
protected:
    string marque;
    int nombrePorts;
};

Ici, marque et nombrePorts sont protégés :
main() ne peut pas les utiliser directement. La différence avec private n'apparaît qu'avec l'héritage.

22Les getters : lire un attribut privé

Un getter est une méthode publique qui renvoie la valeur d'un attribut privé. On lit l'information sans avoir d'accès direct à l'attribut.

🛠️ La syntaxe
C++
typeRetour getNomAttribut()
{
    return nomAttribut;
}

Pour lire la mémoire vive d'un ordinateur :

C++
int getMemoireRAM()
{
    return memoireRAM;
}
  • int :
    le type de la valeur renvoyée.
  • getMemoireRAM() : le nom de la méthode.
  • return memoireRAM; :
    renvoie la valeur de l'attribut.

L'appel, depuis main() :

C++
cout << pc1.getMemoireRAM();

Cette instruction récupère la mémoire vive de l'objet pc1, et l'affiche.

23Les setters : modifier un attribut privé

Un setter est une méthode publique qui modifie la valeur d'un attribut privé. Il peut aussi vérifier la nouvelle valeur avant de l'accepter (section 24).

🛠️ La syntaxe
C++
void setNomAttribut(type nouvelleValeur)
{
    nomAttribut = nouvelleValeur;
}

Pour modifier la mémoire vive d'un ordinateur :

C++
void setMemoireRAM(int ram)
{
    memoireRAM = ram;
}
  • void :
    la méthode ne renvoie aucune valeur.
  • setMemoireRAM() : le nom de la méthode.
  • int ram :
    le paramètre qui contient la nouvelle valeur.
  • memoireRAM = ram; :
    affecte la nouvelle valeur à l'attribut.

L'appel pc1.setMemoireRAM(16); modifie la mémoire vive de l'objet pc1. Le getter et le setter ensemble, dans un programme complet :

💡 get et set

get signifie récupérer une valeur. set signifie affecter, ou modifier, une valeur.

Le nom suit l'attribut, avec une majuscule :

⚠️ Un setter sans contrôle ne protège rien

Ce setter-là accepterait encore -50 :
il recopie la valeur sans la regarder. Le chemin a changé, pas le résultat.

24Vérifier la valeur dans un setter

C'est ici que l'encapsulation sert vraiment. Le setter peut contenir une condition qui vérifie la valeur avant de l'affecter à l'attribut.

Pour empêcher une mémoire vive négative :

C++
void setMemoireRAM(int ram)
{
    if (ram > 0)
    {
        memoireRAM = ram;
    }
    else
    {
        cout << "Valeur invalide !" << endl;
    }
}
  • Si ram est strictement positif, la valeur est affectée à memoireRAM.
  • Sinon, un message d'erreur s'affiche, et l'attribut n'est pas modifié.

Deux appels, l'un accepté, l'autre refusé :

C++
#include <iostream>
using namespace std;

{

    int memoireRAM;

public:

    {
        if (ram > 0)
        {
            memoireRAM = ram;
        }
        else
        {
            cout << "Valeur invalide !" << endl;
        }
    }

    int getMemoireRAM()
    {
        return memoireRAM;
    }
};

int main()
{
    Ordinateur pc1;

    pc1.setMemoireRAM(16);   // Valeur acceptee

Le second appel est refusé :
la mémoire vaut toujours 16 Go. Le -50 de la section 17 ne peut plus passer.

⚠️ Si la toute première valeur est refusée

Un attribut qui n'a jamais reçu de valeur contient n'importe quoi. Si le premier appel est setMemoireRAM(-8), il est refusé, et getMemoireRAM() renvoie une valeur imprévisible.

Une valeur de départ dans la déclaration règle ce cas :
int memoireRAM = 0;

26Le cycle de vie d'un objet

On sait créer une classe et des objets. Reste à savoir ce qui se passe quand un objet naît, comment ses attributs reçoivent leurs premières valeurs, et ce qui se passe quand on n'en a plus besoin.

Deux mécanismes y répondent :
le constructeur et le destructeur. C'est l'objet de cette partie.

📱 Un smartphone a lui aussi une vie

Il est fabriqué :
on assemble ses composants, puis on le configure. Il est utilisé :
on installe des applications, on change les réglages. Il arrive en fin de vie :
on le remplace, il part au recyclage.

Un objet passe donc par trois grandes étapes :

  1. Création et initialisation :
    l'objet est créé, ses attributs reçoivent leurs valeurs.
  2. Utilisation :
    on appelle ses méthodes, ses attributs peuvent changer.
  3. Destruction :
    sa durée de vie se termine, ses ressources sont libérées.

Avec ce qu'on sait déjà, la création et l'initialisation sont deux gestes séparés :

C++
Equipement e1;          // création
e1.nom = "Ordinateur";   // initialisation
e1.numero = 101;
e1.prix = 850;

L'objet existe avant d'avoir ses valeurs. Peut-on les lui donner dès sa création ? Oui :
c'est le rôle du constructeur. Et à la fin, le destructeur fait le ménage.

Chaque objet a une durée de vie :
elle commence à sa création et finit à sa destruction. Entre les deux, il occupe de la mémoire.

27Objets automatiques et objets dynamiques

On peut créer un objet de deux façons. Elles ne gèrent pas sa durée de vie de la même manière.

Un objet automatique

Il est déclaré directement dans un bloc ou une fonction, sans new. Le langage s'occupe seul de sa création et de sa destruction.

C++

#include <string>

    int numero;

    e1.numero = 201;

    e1.afficher();

    return 0;

Numero : 201

  2. On s'en sert par son nom, avec le point :
    e1.nom,
    e1.afficher().
  3. Quand l'exécution quitte le bloc où il est déclaré, son destructeur est appelé tout seul, et l'objet cesse d'exister.

Il est créé explicitement avec l'opérateur new, dans la mémoire dynamique (on dit aussi mémoire libre, free store). Sa vie ne dépend plus du bloc :

C++

28Le constructeur : préparer l'objet dès sa naissance

Un constructeur est une méthode spéciale de la classe, appelée automatiquement à la création d'un objet. Son rôle :
donner aux attributs un état de départ cohérent, avant toute utilisation.

Sans lui, on crée l'objet puis on remplit ses attributs un par un. Ça marche, mais :

  • il faut penser à chaque attribut, et on peut en oublier ;
  • l'objet peut servir avant d'être prêt ;
  • le code se répète pour chaque nouvel objet.
🔑 Les cinq traits d'un constructeur
  1. Il porte exactement le nom de la classe.
  2. Il n'a aucun type de retour, pas même void.
  3. Il est appelé tout seul à la création de l'objet.
  4. Il peut recevoir des paramètres.
  5. Il peut être surchargé :
    une classe peut en avoir plusieurs.
🛠️ La syntaxe
C++
class NomClasse
{
public:
    NomClasse()
    {
        // instructions d'initialisation
    }
};

Il peut être appelé sans paramètre. Il donne à chaque nouvel objet des valeurs prévues d'avance.

31La surcharge des constructeurs

Surcharger, c'est écrire plusieurs constructeurs dans la même classe, chacun avec sa liste de paramètres. Chacun correspond à une façon de créer l'objet.

32Le constructeur de copie

L'entreprise a un équipement, et en veut un second identique. Plutôt que de tout ressaisir, on crée le nouvel objet à partir de l'ancien. C'est le rôle du constructeur de copie.

🛠️ La syntaxe
C++
NomClasse(const NomClasse& autre)
{
    // instructions de copie
}

    l'objet source, celui qu'on copie.
  • & :
    on reçoit une référence à l'objet source, sans le recopier pour le transmettre.
  • const :
    la copie ne peut pas modifier la source.

33La liste d'initialisation

34Le destructeur : la fin de vie

Un destructeur est une méthode spéciale, appelée automatiquement quand un objet termine sa durée de vie. Il fait ce qu'il faut avant que l'objet disparaisse, surtout libérer les ressources qu'il a prises :

  • la mémoire réservée avec new ;
  • un fichier ouvert, à fermer ;
  • une ressource du système, à rendre.
🔑 Les cinq traits d'un destructeur
  1. Il porte le nom de la classe, précédé de ~.
  2. Il n'a aucun type de retour.
  3. Il ne reçoit aucun paramètre.
  4. Il ne peut pas être surchargé : un seul par classe.
  5. Il est appelé tout seul, à la fin de la vie de l'objet.
🛠️ La syntaxe
C++
class NomClasse
{
public:
    ~NomClasse()
    {
        // instructions de nettoyage
    }
};

Le ~ s'obtient avec AltGr + 2 sur un clavier de PC, puis une espace ; sur Mac, Option + N.

36Pourquoi des attributs dynamiques ?

Jusqu'ici, les attributs avaient une taille connue d'avance : int, float, string. Mais une classe Machine qui garde les mesures de ses capteurs n'en a pas toujours le même nombre :
5 pour l'une, 10 pour l'autre, 20 pour une troisième.

Un tableau classique a une taille fixe. Il faudrait prévoir la plus grande, et la plupart des machines gaspilleraient leur place.

Allocation statique et allocation dynamique

Statique :
la taille est écrite dans le code, elle ne change plus.

C++
int mesures[10];   // exactement 10 cases

Dynamique :
la mémoire est réservée pendant l'exécution, à la taille demandée.

C++
#include <iostream>
using namespace std;

int main()
{
    int n;
    cout << "Nombre de mesures : ";
    cin >> n;

    // n entiers, reserves pendant l'execution
    int* mesures = new int[n];

    for (int i = 0; i < n; i++)
    {
        mesures[i] = (i + 1) * 10;
    }

    for (int i = 0; i < n; i++)
    {
        cout << mesures[i] << " ";
    }
    cout << endl;

    // un tableau : delete[]
    delete[] mesures;

    return 0;
}
sortie réelle · saisies : 4
Nombre de mesures : 10 20 30 40
  • new int[n] réserve la place de n entiers ; n est connu seulement à l'exécution.
  • mesures est un pointeur :
    il garde l'adresse de la première case. On s'en sert ensuite comme d'un tableau, mesures[i].
  • delete[] mesures; rend la mémoire. Pour un tableau, c'est delete[], avec les crochets.
⚠️ new va avec delete, new[] avec delete[]

Un objet seul :
new Equipement,
puis delete e1;.
Un tableau :
new int[n],
puis delete[] mesures;.
Les mélanger est une erreur que le compilateur ne voit pas.

38Deux pièges : la fuite et la double libération

La fuite de mémoire

Un programme réserve de la mémoire, puis perd le moyen de la libérer.

C++
int* p = new int[10];
p = new int[20];
  1. Un premier tableau de 10 entiers est réservé ; p garde son adresse.
  2. Un second, de 20 entiers, est réservé ; sa nouvelle adresse remplace l'ancienne dans p.
  3. Plus rien ne connaît l'adresse du premier : on ne peut plus le libérer. Il y a fuite.

Une fuite ne fait pas planter le programme. Elle le fait grossir. Combien coûtent ces 10 entiers perdus ? La taille des types se mesure avec sizeof :

C++
#include <iostream>
using namespace std;

int main()
{
    cout << "int   : " << sizeof(int) << " octets" << endl;
    cout << "float : " << sizeof(float) << " octets" << endl;

    // new int[10] reserve donc :
    cout << "new int[10] : " << 10 * sizeof(int)
         << " octets" << endl;

    return 0;
}
sortie réelle
int   : 4 octets
float : 4 octets
new int[10] : 40 octets
🧰 À la calculatrice : une fuite dans une boucle

Si ces deux lignes sont dans une boucle qui tourne un million de fois, chaque tour perd 40 octets. Le calcul, posé dans la calculatrice :
10 × 4 × 1 000 000 = 40 000 000 octets, soit 40 Mo perdus.

Change le nombre de tours ou la taille du tableau, et revalide :
c'est ainsi qu'un serveur qui tourne des jours finit par manquer de mémoire.

La double libération

On libère deux fois la même zone.

C++
int* p = new int[10];
delete[] p;
delete[] p;     // erreur : deja libere

Le second delete[] rend une zone qui n'est plus à nous. C'est un comportement indéfini :
le programme peut s'arrêter net, ou continuer avec une mémoire abîmée. Le compilateur ne dit rien.

💡 Le réflexe qui évite la seconde

Après un delete[] p;, écrire p = nullptr;. Un delete[] sur un pointeur nul ne fait rien.

39La copie superficielle (shallow copy)

On copie un capteur :
Capteur C2 = C1;.
Sans constructeur de copie écrit, C++ copie les attributs membre par membre. Pour un pointeur, il copie donc l'adresse, pas le tableau.

AttributC1C2, la copie
identifiant101101
mesuresadresse 1000adresse 1000

Les deux objets désignent le même tableau. Une mesure changée par C2 l'est aussi pour C1 :

C++
#include <iostream>
using namespace std;

class Capteur
{
private:
    int identifiant;
    int nombreMesures;
    float* mesures;

public:
    Capteur(int id, int n)
    {
        identifiant = id;
        nombreMesures = n;
        mesures = new float[n];
        for (int i = 0; i < n; i++)
        {
            mesures[i] = 0;
        }
    }

    // Pas de constructeur de copie :
    // C++ copie membre par membre.
    // Pas de destructeur non plus,
    // voir l'explication sous le programme.

    void modifierMesure(int i, float v)
    {
        mesures[i] = v;
    }

    bool partageAvec(const Capteur& autre)
    {
        return mesures == autre.mesures;
    }

    void afficher()
    {
        cout << "Capteur " << identifiant << " : ";
        for (int i = 0; i < nombreMesures; i++)
        {
            cout << mesures[i] << " ";
        }
        cout << endl;
    }
};

int main()
{
    Capteur c1(101, 4);
    c1.modifierMesure(0, 21.5);
    c1.modifierMesure(1, 22.1);
    c1.modifierMesure(2, 23.4);
    c1.modifierMesure(3, 22.8);

    Capteur c2 = c1;   // copie superficielle

    c2.modifierMesure(0, 30.5);

    c1.afficher();
    c2.afficher();

    if (c1.partageAvec(c2))
    {
        cout << "Un seul tableau pour deux objets"
             << endl;
    }

    return 0;
}

On a modifié C2 seul, et C1 affiche aussi 30.5.

💡 Deux détails de ce programme

mesures est privé. On écrit souvent la modification C2.mesures[0] = 30.5; pour la montrer, mais depuis main elle ne compilerait pas. On passe par une méthode, modifierMesure(0, 30.5).

Il n'a pas de destructeur, exprès. Avec un destructeur qui fait delete[] mesures;, C1 et C2 libéreraient le même tableau à la fin de main : une double libération.

⚠️ Les trois risques de la copie superficielle
  • Des données partagées :
    ce que l'un modifie, l'autre le voit.
  • Une double libération :
    chacun tente un delete[] sur le même tableau.
  • Un pointeur invalide :
    si l'un libère le tableau, l'autre garde l'adresse d'une zone rendue.

La solution est la copie profonde :
réserver un tableau neuf pour la copie, y recopier les valeurs, et donner à chaque objet sa propre zone.

Pour un attribut dynamique, déclarer le pointeur ne suffit pas. Il faut réserver la mémoire, initialiser les données, et garder l'adresse. Le constructeur est l'endroit pour le faire, dès la création. Le destructeur, lui, rend la mémoire à la fin.

41La copie profonde (deep copy)

On veut un capteur c2 qui a les mêmes mesures que c1, mais son propre tableau. On écrit donc le constructeur de copie à la main :

  1. il récupère l'identifiant et le nombre de mesures de la source ;
  2. il réserve un nouveau tableau ;
  3. il y copie chaque mesure, une par une.
C++
// Constructeur de copie profonde
Capteur(const Capteur& autre)
{
    identifiant = autre.identifiant;
    nombreMesures = autre.nombreMesures;

    mesures = new float[nombreMesures];

    for (int i = 0; i < nombreMesures; i++)
    {
        mesures[i] = autre.mesures[i];
    }
}

    cout << "\nApres modification de c2 :" << endl;
    c1.afficher();
    c2.afficher();

⚡ Récap 2 minutes

Les idées de la POO

  • Objet = des attributs (ce qu'il est) + des méthodes (ce qu'il fait).
  • Classe = le modèle ; objet = un exemplaire. Capteur c; fabrique l'objet c.
  • Procédural :
    données et fonctions séparées (le C). Objet :
    regroupées dans la classe (le C++).
  • Les quatre principes :
    encapsulation (regrouper et protéger), abstraction (montrer l'utile), héritage (spécialiser une classe), polymorphisme (une opération, plusieurs comportements).
  • La classe se ferme par };, comme une struct.

Les bases du C++

  • #include <iostream>, sans .h ; fichier en .cpp.
  • std::cout ou using namespace std; puis cout : les deux sont justes.
  • cout << affiche, cin >> lit :
    les chevrons pointent dans le sens où va la donnée.
  • Ni code de format, ni & : le type est deviné.
  • endl ou \n pour passer à la ligne.
  • Des guillemets droits ", jamais « » ni les guillemets courbes d'un traitement de texte.
  • cin >> s'arrête à l'espace, getline(cin, nom) lit la ligne.
  • cin >> age; puis getline → il faut cin.ignore(); entre les deux, sinon le nom reste vide.

Classes et objets

  • class Nom { ... }; :
    attributs et méthodes, et le point-virgule final.
  • Privé par défaut :
    sans public:, main ne peut pas toucher aux attributs.
  • Ordinateur pc1; crée un objet ; pc1.marque et pc1.afficher() s'en servent.
  • void Ordinateur::afficher() définit une méthode hors de la classe.

L'encapsulation

  • Attributs private, méthodes public :
    la forme habituelle d'une classe.
  • private : la classe seule. protected : la classe et ses filles. public : tout le monde.
  • Sans spécificateur, un membre de classe est privé.
  • Getter :
    int getMemoireRAM() { return memoireRAM; } lit la valeur.
  • Setter :
    void setMemoireRAM(int ram) la modifie, et peut la refuser avec un if (ram > 0).
  • Une valeur refusée laisse l'attribut tel qu'il était.
  • pc.marque = ... sur un attribut privé : le compilateur refuse. Une méthode de la classe, elle, y a accès.

Constructeurs et destructeurs

  • Constructeur :
    le nom de la classe, aucun type de retour, appelé à la création. Par défaut Equipement(), avec paramètres, de copie Equipement(const Equipement& autre).
  • Surcharge :
    plusieurs constructeurs, des paramètres différents ; le compilateur choisit d'après les arguments.
  • Liste d'initialisation :
    : nom(n), numero(num) avant l'accolade.
  • Destructeur :
    ~Equipement(), sans paramètre, un seul par classe. Automatique : à la fin du bloc. Dynamique : au delete.
  • Le dernier créé est le premier détruit.
  • new / delete pour un objet, new[] / delete[] pour un tableau.
  • Fuite : une adresse perdue. Double libération :
    deux delete[] sur la même zone.
  • Copie superficielle :
    deux objets, un seul tableau. Copie profonde :
    un tableau neuf, les valeurs recopiées.
