Langage C — exercices

Les huit exercices du TP2 — le langage, jusqu'aux boucles — puis les dix du TP3, sur les fonctions et les tableaux. Chaque correction a été compilée puis exécutée avant d'être écrite ici, et l'est de nouveau à chaque contrôle du dépôt.

🎯 Comment travailler ce chapitre

Le C ne s'apprend pas en lisant. Ouvrez un compilateur — en ligne sur onlinegdb.com, ou Code::Blocks sur le poste — et tapez chaque programme. Vous ferez des erreurs de compilation : c'est le but. Apprendre à lire un message d'erreur est la moitié du métier.

Cherchez d'abord seul, au moins dix minutes. La correction ne vaut que si vous savez ce que vous n'avez pas trouvé.

01TP 2 · Appréciation d'une note

1Note sur 20 → appréciation Facile

Demander une note sur 20 et afficher une appréciation :

NoteAppréciation
note < 10Insuffisant
10 ⩽ note < 12Passable
12 ⩽ note < 14Assez bien
14 ⩽ note < 16Bien
note ⩾ 16Très bien

Le programme doit aussi vérifier que la note est comprise entre 0 et 20. Sinon, afficher Note invalide.

✅ Correction
C
#include <stdio.h>

int main(void)
{
    float note;

    printf("Entrez une note sur 20 : ");
    scanf("%f", &note);

    if (note < 0 || note > 20) {
        printf("Note invalide\n");
    } else if (note < 10) {
        printf("Insuffisant\n");
    } else if (note < 12) {
        printf("Passable\n");
    } else if (note < 14) {
        printf("Assez bien\n");
    } else if (note < 16) {
        printf("Bien\n");
    } else {
        printf("Tres bien\n");
    }
    return 0;
}
🧰 Pourquoi else if et pas cinq if séparés

Avec une chaîne else if, dès qu'une condition est vraie toutes les suivantes sont ignorées. C'est ce qui permet d'écrire note < 12 tout court : on sait déjà qu'elle n'est pas inférieure à 10, puisque la branche précédente n'a pas été prise.

Avec cinq if indépendants, il faudrait écrire if (note >= 10 && note < 12) — plus long, et plus facile à rater.

Une chaîne else if se lit comme un escalier : on descend jusqu'à la première marche qui tient.

⚠️ Le test de validité doit venir EN PREMIER

Si l'on place if (note < 0 || note > 20) en dernier, il ne sera jamais atteint : une note de 25 aurait déjà déclenché note >= 16 → Très bien. Une note de −5 aurait déclenché note < 10 → Insuffisant.

Dans une chaîne else if, l'ordre est la logique. Le cas d'erreur se teste avant les cas normaux.

💡 float plutôt que int

Une note peut valoir 12,5. Avec int note;, scanf("%d", …) lirait 12 et laisserait ,5 dans le tampon — la suite du programme partirait en vrille. Le type doit correspondre à la réalité de la donnée, pas à ce qui est le plus simple à écrire.

Vérifié à l'exécution pour 8 → Insuffisant, 11 → Passable, 13 → Assez bien, 15 → Bien, 18 → Très bien, 25 → Note invalide.

02TP 2 · Somme de 1 à N

2Accumuler dans une boucle Facile

Demander un entier N puis calculer la somme des nombres de 1 à N.

exemple attendu
N = 5
1 + 2 + 3 + 4 + 5 = 15
✅ Correction
C
#include <stdio.h>

int main(void)
{
    int n, i, somme = 0;

    printf("Entrez N : ");
    scanf("%d", &n);

    for (i = 1; i <= n; i++) {
        somme = somme + i;
    }

    printf("La somme de 1 a %d vaut %d\n", n, somme);
    return 0;
}
⚠️ int somme = 0; — le = 0 n'est pas décoratif

Écrire int somme; puis somme = somme + i; additionne à une valeur inconnue : celle qui traînait en mémoire. Le programme compile, tourne, et donne un résultat différent d'une exécution à l'autre.

C'est le réflexe à prendre : tout accumulateur s'initialise. À 0 pour une somme, à 1 pour un produit.

🧰 La vérification qui ne coûte rien

Gauss a montré que la somme de 1 à n vaut n × (n + 1) / 2. Pour n = 5 : 5 × 6 / 2 = 15 ✔

Un test rapide de votre programme : si la boucle et la formule ne donnent pas la même chose, c'est la boucle qui a tort.

C — contrôle
printf("controle : %d\n", n * (n + 1) / 2);

Vérifié à l'exécution : N = 5 donne bien 15.

03TP 2 · Menu de gestion du serveur

3Un menu avec switch Facile

Afficher le menu suivant, lire un choix entre 1 et 5, et réagir en conséquence.

affichage attendu
===== GESTION DU SERVEUR =====
1. Démarrer le serveur
2. Arrêter le serveur
3. Redémarrer le serveur
4. Afficher l'état du serveur
5. Quitter

Votre choix :

1 → Le serveur démarre… · 2 → Le serveur s'arrête… · 3 → Le serveur redémarre… · 4 → État du serveur : ACTIF · 5 → Au revoir · tout autre choix → Choix invalide.

✅ Correction
C
#include <stdio.h>

int main(void)
{
    int choix;

    printf("===== GESTION DU SERVEUR =====\n");
    printf("1. Demarrer le serveur\n");
    printf("2. Arreter le serveur\n");
    printf("3. Redemarrer le serveur\n");
    printf("4. Afficher l'etat du serveur\n");
    printf("5. Quitter\n\n");
    printf("Votre choix : ");
    scanf("%d", &choix);

    switch (choix) {
        case 1: printf("Le serveur demarre...\n");    break;
        case 2: printf("Le serveur s'arrete...\n");   break;
        case 3: printf("Le serveur redemarre...\n");  break;
        case 4: printf("Etat du serveur : ACTIF\n");  break;
        case 5: printf("Au revoir\n");                break;
        default: printf("Choix invalide\n");
    }
    return 0;
}
⚠️ Enlevez un break et observez

Supprimez celui du case 1 puis choisissez 1 : le programme affiche Le serveur démarre… puis Le serveur s'arrête… Il ne s'arrête qu'au premier break rencontré.

Faites l'expérience une fois : vous n'oublierez plus jamais de break.

🧰 Les accents dans un terminal

La correction écrit Demarrer sans accent. Ce n'est pas de la négligence : selon l'encodage de la console — surtout sous Windows — un é peut s'afficher Ã©. Tant que l'encodage n'est pas maîtrisé, mieux vaut un texte sans accent qu'un affichage illisible.

Dans le rendu de votre TP, gardez les accents de l'énoncé et signalez ce point : cela montre que vous l'avez compris.

💡 Aller plus loin : redemander tant que le choix est invalide

Un vrai menu ne s'arrête pas après un mauvais choix. C'est exactement le cas d'usage du do…while :

C
do {
    printf("Votre choix : ");
    scanf("%d", &choix);
} while (choix < 1 || choix > 5);

Il faut au moins une saisie : la condition se teste donc après.

Vérifié à l'exécution : 1 → Le serveur démarre…, 4 → État du serveur : ACTIF, 9 → Choix invalide.

04TP 2 · Nombre inversé

4Retourner un entier Moyen

Demander un entier positif et afficher ce nombre à l'envers. Si le nombre n'est pas positif, afficher Erreur : le nombre doit être positif.

exemple attendu
Entrez un nombre : 12345
Nombre inversé : 54321
✅ Correction
C
#include <stdio.h>

int main(void)
{
    int nombre, inverse = 0, chiffre;

    printf("Entrez un nombre : ");
    scanf("%d", &nombre);

    if (nombre <= 0) {
        printf("Erreur : le nombre doit etre positif.\n");
        return 0;
    }

    while (nombre > 0) {
        chiffre = nombre % 10;            /* le dernier chiffre */
        inverse = inverse * 10 + chiffre; /* on le pousse à gauche */
        nombre  = nombre / 10;            /* on le retire du nombre */
    }

    printf("Nombre inverse : %d\n", inverse);
    return 0;
}
🔍 Le mécanisme : dépiler d'un côté, empiler de l'autre

Deux opérations font tout le travail, et ce sont exactement celles du chapitre d'arithmétique de 1re année :

  • nombre % 10 donne le dernier chiffre (le reste de la division par 10) ;
  • nombre / 10 retire ce dernier chiffre (division entière).

Et inverse * 10 + chiffre décale ce qu'on a déjà d'un cran vers la gauche pour faire de la place au nouveau chiffre.

Tournombrechiffreinverse
départ12345—0

4125432
50154321

Quand nombre atteint 0, la condition devient fausse et la boucle s'arrête d'elle-même. On n'a jamais eu besoin de compter les chiffres.

⚠️ Pourquoi while et non for

On ne sait pas combien de chiffres contient le nombre — c'est justement ce qu'on refuse de compter. Le nombre de tours est donc inconnu : c'est la définition même du while.

« Combien de tours ? » est toujours la bonne question pour choisir sa boucle.

Vérifié à l'exécution : 12345 → 54321, et −3 → le message d'erreur.

05TP 2 · Le jeu du nombre caché

5Deviner, avec compteur de coups Moyen

Le premier joueur saisit un entier ; le second doit le deviner, avec autant de tentatives qu'il le souhaite. Après chaque échec, indiquer si le nombre cherché est plus grand ou plus petit. Compter les tentatives et afficher le score à la fin.

✅ Correction
C
#include <stdio.h>

int main(void)
{
    int secret, proposition, tentatives = 0;

    printf("Joueur 1, entrez le nombre a deviner : ");
    scanf("%d", &secret);

    do {
        printf("Proposition : ");
        scanf("%d", &proposition);
        tentatives++;

        if (proposition < secret) {
            printf("  C'est plus grand.\n");
        } else if (proposition > secret) {
            printf("  C'est plus petit.\n");
        }
    } while (proposition != secret);

    printf("Bravo ! Trouve en %d coup(s).\n", tentatives);
    return 0;
}
🧰 Trois décisions qui font tout l'exercice
  • do…while — il faut au moins une proposition avant de pouvoir la comparer. Avec un while, il faudrait une première saisie en dehors de la boucle : deux fois le même code.
  • Pas de else pour le cas gagnant — quand la proposition est juste, aucun des deux messages ne s'affiche, et la condition de boucle suffit à sortir.
  • tentatives++ dans la boucle, juste après la saisie : on compte ce qui a été joué, y compris le coup gagnant.
⚠️ « Plus grand » : plus grand que quoi ?

Si la proposition est inférieure au secret, c'est le nombre à trouver qui est plus grand. La tentation est d'écrire « C'est plus petit » parce qu'on pense à la proposition.

Le message doit parler du nombre cherché, pas de la proposition. Faites l'essai avec un nombre connu : on s'en rend compte tout de suite.

💡 Faire tirer le nombre par l'ordinateur
C
#include <stdlib.h>
#include <time.h>

srand(time(NULL));              /* une seule fois, au début */
int secret = rand() % 100 + 1;  /* entre 1 et 100 */

Sans srand(time(NULL)), rand() donne la même suite à chaque lancement : le secret serait toujours le même.

Vérifié à l'exécution : secret 42, propositions 50 puis 30 puis 42 → « plus petit », « plus grand », « Trouvé en 3 coup(s) ».

06TP 2 · Nombre presque parfait

6Somme des diviseurs propres Moyen

Un nombre presque parfait est un entier naturel dont la somme des diviseurs — lui-même exclu — est inférieure de 1 à lui-même.

Exemple : 16 est presque parfait, car 1 + 2 + 4 + 8 = 15 = 16 − 1.

Écrire un programme qui demande un nombre et dit s'il est presque parfait.

✅ Correction
C
#include <stdio.h>

int main(void)
{
    int n, i, somme = 0;

    printf("Entrez un nombre : ");
    scanf("%d", &n);

    for (i = 1; i < n; i++) {      /* i < n : on exclut n lui-même */
        if (n % i == 0) {
            somme = somme + i;
        }
    }

    printf("Somme des diviseurs propres : %d\n", somme);

    if (somme == n - 1) {
        printf("%d est presque parfait.\n", n);
    } else {
        printf("%d n'est pas presque parfait.\n", n);
    }
    return 0;
}
🧰 Traduire l'énoncé, mot à mot
L'énoncé dit……qui s'écrit
« i divise n »n % i == 0
« hormis lui-même »i < n, et non i <= n
« inférieure de 1 à lui-même »somme == n - 1

Un énoncé de maths se traduit ligne par ligne. Quand on bloque, c'est presque toujours qu'une phrase n'a pas été traduite.

💡 Les presque parfaits sont les puissances de 2

Testez 8 : 1 + 2 + 4 = 7 = 8 − 1 ✔. Puis 32 : 1 + 2 + 4 + 8 + 16 = 31 ✔. Puis 12 : 1 + 2 + 3 + 4 + 6 = 16, ce qui fait 4 de trop ✘.

Les diviseurs propres de 2k sont exactement 1, 2, 4, …, 2k−1, et leur somme vaut 2k − 1. Aucun autre nombre presque parfait n'est connu.

Un bon jeu de tests : 8 et 16 doivent répondre oui, 12 doit répondre non.

⚠️ i <= n casserait tout

Avec i <= n, la somme inclurait n lui-même : pour 16 elle vaudrait 31 au lieu de 15, et aucun nombre ne serait jamais déclaré presque parfait. Le programme tournerait sans erreur et répondrait toujours non.

Le pire des bugs : celui qui donne une réponse plausible.

Vérifié à l'exécution : 16 → presque parfait, 8 → presque parfait, 12 → ne l'est pas.

07TP 2 · Les nombres formés par trois chiffres

7Les six permutations Difficile

Saisir un entier de trois chiffres non nuls, puis afficher tous les nombres que l'on peut former avec ces chiffres.

exemple attendu
N = 578
Les nombres formés par les chiffres de N sont : 578, 587, 785, 758, 857, 875.
✅ Correction
C
#include <stdio.h>

int main(void)
{
    int n, c1, c2, c3;

    printf("Entrez un entier de trois chiffres non nuls : ");
    scanf("%d", &n);

    if (n < 100 || n > 999) {
        printf("Erreur : il faut trois chiffres.\n");
        return 0;
    }

    c1 = n / 100;          /* centaines */
    c2 = (n / 10) % 10;    /* dizaines  */
    c3 = n % 10;           /* unités    */

    if (c1 == 0 || c2 == 0 || c3 == 0) {
        printf("Erreur : les trois chiffres doivent etre non nuls.\n");
        return 0;
    }

    printf("%d %d %d %d %d %d\n",
           c1*100 + c2*10 + c3,  c1*100 + c3*10 + c2,
           c2*100 + c1*10 + c3,  c2*100 + c3*10 + c1,
           c3*100 + c1*10 + c2,  c3*100 + c2*10 + c1);
    return 0;
}
🧰 Extraire les trois chiffres
ChiffreCalculSur 578
centainesn / 100578 / 100 = 5
dizaines(n / 10) % 1057 % 10 = 7
unitésn % 10578 % 10 = 8

Là encore, / et % sur des entiers : les deux seules opérations dont on a besoin pour découper un nombre.

💡 Pourquoi exactement six, et pourquoi « non nuls »

Trois chiffres distincts donnent 3 × 2 × 1 = 6 arrangements : trois choix pour la position des centaines, deux pour celle des dizaines, un pour le reste.

La condition « non nuls » de l'énoncé s'explique ainsi : avec un 0 — disons 508 — la permutation 085 ne serait plus un nombre de trois chiffres, elle vaudrait 85. La règle évite ce cas particulier.

Si les chiffres se répètent (515), les six résultats contiennent des doublons. L'énoncé ne l'interdit pas ; on peut le signaler dans le compte rendu.

⚠️ L'ordre d'affichage n'est pas celui de l'énoncé

Ce programme affiche 578 587 758 785 857 875 ; l'énoncé annonce 578, 587, 785, 758, 857, 875. Les six nombres sont les mêmes — seul l'ordre diffère, et l'énoncé ne fixe aucun ordre.

Avant de croire à une erreur, comparez les ensembles. Ici tout est juste.

Vérifié à l'exécution : 578 donne bien ces six nombres.

08TP 2 · Six programmes à tracer

« Que vont afficher les programmes suivants ? » L'exercice le plus formateur du TP : il ne demande pas d'écrire du code, mais de le lire exactement. Les six résultats ci-dessous ont été obtenus en compilant et en exécutant chaque programme.

🔧 Corrigé — main() sans type ne compile plus

Les six programmes de l'énoncé commencent par main(), sans int. C'était légal dans le C des origines : le type int était sous-entendu. Depuis la norme C99, ce n'est plus accepté — un compilateur d'aujourd'hui refuse les six programmes tels qu'imprimés :

message du compilateur
error: type specifier missing, defaults to 'int';
       ISO C99 and later do not support implicit int

Il manque aussi #include <stdio.h>, sans quoi printf n'est pas déclarée. La diapositive « Structure simplifiée d'un programme C » écrit d'ailleurs correctement int main() : c'est l'énoncé du TP qui n'a pas suivi.

Les corrections ci-dessous rétablissent #include et int main(). Rien d'autre n'a été touché : les pièges restent entiers.

①Le point-virgule qui vide la boucle Moyen

C
#include <stdio.h>
int main()
{ int n=5, i;
    for(i=2; i<n; i++);
    printf("%d\n",i);
}
✅ Correction
sortie réelle
5

Le ; juste après for(...) est le corps de la boucle : un corps vide. La boucle se contente donc de faire monter i de 2 à 5, puis s'arrête quand i < 5 devient faux.

Le printf, qui n'a jamais appartenu à la boucle, s'exécute une seule fois et affiche la valeur de sortie : 5.

⚠️ Sans ce point-virgule, la réponse serait 2 3 4

C'est toute la différence entre « la boucle affiche » et « la boucle compte, puis on affiche ». Un caractère.

④Ternaire, dans le mauvais sens Facile

C
#include <stdio.h>
int main()

✅ Correction
sortie réelle
15

a > b s'écrit 15 > 23 : faux. On prend donc la branche de droite — a — qui vaut 15.

⚠️ Ce n'est pas le maximum

La forme habituelle est (a>b) ? a : b, qui donne le plus grand. Ici les deux branches sont inversées : ? b : a. Le programme renvoie le minimum.

Lire un ternaire, c'est lire trois choses dans l'ordre : la condition, puis ce qu'on fait si vrai, puis si faux. Ne jamais le reconnaître « de loin ».

⑥Encore le point-virgule Moyen

C
#include <stdio.h>
int main()
{ int m=5, j;
    for(j=3; j<=m; ++j);
    printf("%d-",j);
}
✅ Correction
sortie réelle
6-

Même piège que le programme ①, avec une nuance : la condition est j <= m, c'est-à-dire j <= 5. La boucle s'arrête donc quand j vaut 6, et non 5.

++j ou j++ ne change rien ici : personne n'utilise la valeur renvoyée, seul l'effet compte.

🧰 La règle générale des deux programmes

Après une boucle for terminée normalement, le compteur vaut la première valeur qui rend la condition fausse :

  • i < 5 → i sort à 5
  • j <= 5 → j sort à 6

C'est aussi la raison pour laquelle un tableau de 5 cases se parcourt avec i < 5 : à la sortie, i vaut 5, soit exactement une case de trop — celle qui n'existe pas.

09TP 3 · Quatre fonctions simples

1La moyenne de deux mesures Facile

Écrire une fonction Moyenne qui reçoit deux nombres réels et retourne leur moyenne. Le programme principal doit demander deux mesures, appeler la fonction et afficher le résultat.

✅ Correction
C
#include <stdio.h>

float Moyenne(float a, float b)
{
    return (a + b) / 2;
}

int main(void)
{
    float m1, m2;

    printf("Saisir la première mesure : ");
    scanf("%f", &m1);
    printf("Saisir la deuxième mesure : ");
    scanf("%f", &m2);

    printf("\nLa moyenne est : %.2f\n", Moyenne(m1, m2));
    return 0;
}
sortie réelle — saisies : 18.5 puis 21.5
Saisir la première mesure : 18.5
Saisir la deuxième mesure : 21.5

La moyenne est : 20.00
⚠️ (a + b) / 2 et non a + b / 2

La division est prioritaire sur l'addition. Sans les parenthèses, le programme calcule a + (b / 2), soit 29,25 au lieu de 20. Il compile, il tourne, et il se trompe.

12TP 3 · La méthode, en quatre gestes

Les neuf exercices suivent le même schéma. Une fois qu'on l'a vu, le TP se déroule tout seul.

Écrire une fonction, dans l'ordre
#GesteLa question à se poser
1Ce qu'elle reçoitde quoi a-t-elle besoin pour travailler ? → les paramètres
2Ce qu'elle rendune valeur, ou un affichage ? → le type de retour, ou void

🧭 Le test qui dit si le découpage est bon

Une fonction doit pouvoir se décrire en une phrase sans « et ».

« Calcule la moyenne d'un tableau » — bonne fonction. « Saisit les notes et calcule la moyenne et affiche le résultat » — trois fonctions déguisées en une.

C'est précisément pour cela que l'exercice 9 en demande cinq : chacune fait une chose, et main ne fait qu'orchestrer.

⚠️ Les quatre fautes qui reviennent dans ce TP

La casse. Moyenne et moyenne sont deux fonctions différentes. Choisissez une convention et tenez-la.

La division entière. perdus / envoyes entre deux int donne 0. Il faut (float).

La borne de boucle. i < n, jamais i <= n.

La taille oubliée. Un tableau passé à une fonction a besoin de son n.

🤔 Pourquoi les prototypes sont-ils groupés en haut, aux exercices 8 et 9 ?

Pour que main vienne en premier. Le compilateur a besoin de connaître chaque fonction avant le premier appel ; les prototypes le lui disent, et les définitions peuvent alors venir après.

L'autre organisation — toutes les définitions avant main — marche aussi. Mais à cinq fonctions, il faut descendre au bas du fichier pour trouver le programme principal.

Sur une copie, grouper les prototypes montre qu'on a compris à quoi ils servent. C'est gratuit, et ça se voit.

🧭 « Par serveur » veut dire « par ligne »

L'énoncé dit « les connexions établies par chaque serveur ». Celui qui établit, c'est la ligne. On somme donc une ligne à la fois : i dehors, j dedans, et la remise à zéro de somme dans la boucle des i.

Si l'énoncé avait dit « connexions reçues par chaque serveur », il aurait fallu échanger les deux boucles. Même matrice, autre question, autre code.

⚠️ somme se remet à zéro à chaque ligne

Le symptôme est reconnaissable : les valeurs montent toujours, et la dernière est juste. C'est une faute qui passe presque inaperçue sur des données bien choisies.

12Cinq jours de températures sur quatre serveurs Moyen

Une matrice 5 × 4 de float : une ligne par jour, une colonne par serveur. Saisir, afficher, puis donner la température moyenne de chaque serveur, le nombre de relevés au-dessus de 30 °C, et la température maximale enregistrée.

✅ Correction
C
#include <stdio.h>

#define JOURS    5
#define SERVEURS 4

int main(void)
{
    float temperatures[JOURS][SERVEURS];
    int i, j, chaudes = 0;
    float maximum;

    for (i = 0; i < JOURS; i++) {
        for (j = 0; j < SERVEURS; j++) {
            printf("Jour %d, serveur %d : ", i + 1, j + 1);
            scanf("%f", &temperatures[i][j]);
        }
    }

    printf("\nReleve des temperatures :\n");
    for (i = 0; i < JOURS; i++) {
        for (j = 0; j < SERVEURS; j++)
            printf("%8.1f", temperatures[i][j]);
        printf("\n");
    }

    printf("\nTemperature moyenne de chaque serveur :\n");
    for (j = 0; j < SERVEURS; j++) {
        float somme = 0;
        for (i = 0; i < JOURS; i++)
            somme += temperatures[i][j];
        printf("  serveur %d : %.2f C\n", j + 1, somme / JOURS);
    }

    maximum = temperatures[0][0];
    for (i = 0; i < JOURS; i++)
        for (j = 0; j < SERVEURS; j++) {

                chaudes++;
            if (temperatures[i][j] > maximum)
                maximum = temperatures[i][j];
        }

    printf("\nReleves au-dessus de 30 C : %d\n", chaudes);
    printf("Temperature maximale : %.1f C\n", maximum);
    return 0;

🧭 Ici, la boucle du dehors est celle des colonnes

« La moyenne de chaque serveur » — et le serveur est la colonne. On met donc j à l'extérieur et i à l'intérieur : on descend une colonne, on divise par 5, on passe à la suivante.

C'est le seul endroit du TP où les deux boucles sont inversées par rapport à l'habitude. Les écrire dans le mauvais ordre donne la moyenne du jour, pas celle du serveur — cinq valeurs au lieu de quatre, ce qui se voit.

⚠️ Le maximum part de la première case, pas de zéro

maximum = temperatures[0][0]; avant le parcours. Partir de 0 marche par chance ici — les températures sont positives — et serait faux dès qu'une mesure descend sous zéro, ce qui arrive dans un local technique mal chauffé.

Deux questions, un seul parcours : compter les relevés chauds et chercher le maximum tiennent dans la même double boucle.

💡 %.2f, %.1f : le format ne change pas la valeur

La moyenne du serveur 3 vaut 31.98 à deux décimales. Affichée en %.1f, elle donnerait 32.0 — arrondie à l'affichage, pas en mémoire. Le choix du format est une décision de lisibilité, jamais de calcul.

Un tableau 4 × 5 : une ligne par utilisateur, une colonne par jour, et le nombre de tentatives de connexion dans chaque case. Saisir, afficher, puis écrire une fonction totalUtilisateur() qui reçoit le tableau et un numéro de ligne et renvoie le total de cette ligne. ⚠️ int t[][5] — la seconde taille est obligatoire

Le compilateur doit savoir la longueur d'une ligne pour trouver où commence la suivante : t[i][j] se trouve en mémoire à la position i × 5 + j. Sans ce 5, il ne peut rien calculer, et int t[][] est refusé — array has incomplete element type, un message qui ne dit pas franchement ce qui manque.

On peut écrire les deux tailles, int t[4][5] : c'est accepté, et la première est simplement ignorée.

🧭 Le champion se cherche pendant qu'on affiche

record est initialisé avec le total du premier utilisateur, pas avec 0. La boucle d'affichage sert aussi à comparer : un seul parcours, et meilleur retient l'indice, pas la valeur.

Retenir l'indice plutôt que la valeur est le réflexe à prendre : avec l'indice on peut tout retrouver — le nom, la ligne, les cinq jours de détail. Avec la seule valeur, on ne sait plus à qui elle appartient.

🤔 Et si deux utilisateurs étaient à égalité ?

Le test est total > record, strictement supérieur : en cas d'égalité, c'est le premier rencontré qui reste désigné.

Avec >=, ce serait le dernier. Aucune des deux réponses n'est fausse — mais l'énoncé ne dit pas laquelle il veut, et c'est le genre de détail qu'on signale en une ligne sur une copie.

⚠️ Les trois fautes de ce TP

L'accumulateur non remis à zéro entre deux lignes : les totaux montent toujours, et seul le dernier est juste.

Les boucles dans le mauvais ordre : on obtient la moyenne du jour au lieu de celle du serveur. Le compte des résultats le trahit — cinq au lieu de quatre.

La seconde taille oubliée dans le paramètre d'une fonction : le programme ne compile pas, et le message parle d'un type incomplet.

TP 3 — fonctions et tableaux

  • Une fonction, une phrase sans « et ». Si la description en contient un, il y a deux fonctions.
  • (a + b) / 2 — les parenthèses, sinon la division passe avant l'addition.
  • (float) perdus / envoyes — sans la conversion, deux entiers donnent un entier, et le taux vaut 0.
  • 0 <= v && v <= 255 — l'écriture mathématique 0 <= v <= 255 compile et est toujours vraie.
  • %% pour afficher un pourcentage.
  • max = t[0], boucle à partir de i = 1 — partir de 0 est faux dès qu'une valeur est négative.
  • position = -1 pour dire « pas trouvé » : 0 est un indice valide.
  • La position, c'est l'indice : on compte 0 1 2 3 4, donc la cinquième valeur est à la position 4.
  • Un tableau passé à une fonction perd sa taille : on passe toujours n.
  • Mais la fonction peut le remplir : c'est pour cela que SaisirTableau() ne retourne rien.

TP 4 — les tableaux à deux dimensions

  • Une boucle dans une boucle, toujours. Ce qui change d'un exercice à l'autre, c'est laquelle est à l'extérieur.
  • « Par ligne » ou « par colonne » : l'énoncé le dit, il suffit de le lire. « Établies PAR un serveur » → la ligne. « Moyenne D'UN serveur » → la colonne.
  • L'accumulateur se remet à zéro au début de chaque ligne — pas avant la double boucle.
  • int t[][5] : la seconde taille ne s'omet jamais dans un paramètre de fonction.
  • Le maximum part de la première case, jamais de 0.
  • Retenir l'indice, pas la valeur : avec l'indice on retrouve tout le reste.
  • Le dernier élément d'un [3][4] est [2][3] — la taille moins un, dans chaque dimension.
