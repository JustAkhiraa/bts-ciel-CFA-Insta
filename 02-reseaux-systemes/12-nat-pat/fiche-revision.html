02Les configurations

Les trois, côte à côte

! ══ STATIQUE ══
R2(config)# ip nat inside source static 192.168.10.254 209.165.201.5

! ══ DYNAMIQUE ══
R2(config)# ip nat pool NAT-POOL1 209.165.200.226 209.165.200.240 netmask 255.255.255.224
R2(config)# access-list 1 permit 192.168.0.0 0.0.255.255     ← masque GÉNÉRIQUE
R2(config)# ip nat inside source list 1 pool NAT-POOL1

! ══ PAT ══
R2(config)# access-list 1 permit 192.168.0.0 0.0.255.255
R2(config)# ip nat inside source list 1 interface s0/1/0 overload
!  ou :     ip nat inside source list 1 pool NAT-POOL1 overload

! ══ OBLIGATOIRE dans les 3 cas ══
R2(config)# interface fa0/0
R2(config-if)# ip nat inside          ← côté LAN
R2(config)# interface s0/1/0
R2(config-if)# ip nat outside         ← côté INTERNET

Les 3 pièges de syntaxe

  1. Masque générique dans l'ACL : 0.0.255.255, pas 255.255.0.0. 0 = doit correspondre, 1 = peu importe
  2. Nom du pool sensible à la casse — NAT-POOL1 ≠ nat-pool1
  3. netmask obligatoire dans ip nat pool

Redirection de port

ip nat inside source static tcp \
  192.168.10.254 80 209.165.200.225 80

C'est l'« ouverture de port » d'une box : exposer un seul service quand on n'a qu'une adresse publique.

Avantages / inconvénients

+ Conserve les adresses publiques · souplesse · cohérence interne · sécurité

− Performances · fin du bout en bout · perte de traçabilité · tunneling complexe · connexions TCP perturbées

⚠️ La NAT n'est pas un pare-feu. Elle masque, elle ne filtre pas.

⚡ Si vous ne reteniez que trois choses

  • Inside/Outside = quel côté. Local/Global = privée ou publique.
  • ip nat inside + ip nat outside — sans elles, rien ne se traduit, et rien ne le dit.
  • overload = PAT. Sans ce mot, le pool s'épuise.
