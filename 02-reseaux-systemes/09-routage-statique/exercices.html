Routage statique — exercices

Écrire des routes, lire une table, et surtout retrouver celle qui manque.

🎯

La méthode qui ne rate jamais

Pour chaque routeur, faites deux colonnes : « ce qu'il connaît déjà » (ses réseaux connectés) et « ce qu'il ignore ». La seconde colonne est la liste des routes à écrire. Puis recommencez pour le retour — c'est l'oubli le plus coûteux du chapitre.

01Configurer les interfaces

1Mettre un routeur en service Facile

Le routeur R1 doit être configuré ainsi :

  • Fa0/0 → LAN, 192.168.1.1/24, description « LAN Administratif » ;
  • S0/0/0 → liaison vers R2, 192.168.2.1/30, R1 est du côté DCE ;
  • une interface de bouclage 10.1.1.1/32 pour les tests.

Écrivez la configuration, puis la commande de vérification et ce qu'elle doit afficher.

✅ Correction
Cisco IOS — R1
R1# configure terminal

R1(config)# interface fa0/0
R1(config-if)# description LAN Administratif
R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface s0/0/0
R1(config-if)# description Liaison vers R2
R1(config-if)# ip address 192.168.2.1 255.255.255.252
R1(config-if)# clock rate 64000              ← côté DCE UNIQUEMENT
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface loopback 0
R1(config-if)# ip address 10.1.1.1 255.255.255.255
R1(config-if)# exit                          ← PAS de no shutdown : elle est UP d'office

R1(config)# end
R1# copy running-config startup-config

La vérification

Cisco IOS
R1# show ip interface brief

Interface        IP-Address     OK?  Method  Status  Protocol
FastEthernet0/0  192.168.1.1    YES  manual  up      up
Serial0/0/0      192.168.2.1    YES  manual  up      up
Loopback0        10.1.1.1       YES  manual  up      up
⚠️ Les trois pièges de cet exercice
  • Le masque /30 = 255.255.255.252, pas 255.255.255.0. Un /30 offre exactement 2 adresses utilisables — c'est le masque standard d'une liaison point à point.
  • clock rate uniquement côté DCE. Le taper des deux côtés ne casse rien, mais ne pas le taper du tout laisse l'interface série en up / down. Pour savoir de quel côté on est : show controllers s0/0/0.
  • Pas de no shutdown sur la loopback. C'est une interface logicielle : elle est up dès sa création.
🧰 Interpréter up / down sur une série

Status: up mais Protocol: down sur une interface série signifie que le câble est bien branché (couche 1) mais que la couche 2 ne s'établit pas. Sur une liaison de laboratoire, la cause est presque toujours l'horloge manquante côté DCE.

02Écrire des routes statiques

2Les trois méthodes Facile

R1 doit joindre le réseau 192.168.3.0/24. Le tronçon suivant est 192.168.2.2, atteignable par l'interface S0/0/0.

Écrivez la route selon les trois méthodes, et indiquez laquelle vous choisiriez ici.

✅ Correction
Cisco IOS
! 1 — adresse du tronçon suivant seule
R1(config)# ip route 192.168.3.0 255.255.255.0 192.168.2.2

! 2 — interface de sortie seule
R1(config)# ip route 192.168.3.0 255.255.255.0 s0/0/0

! 3 — entièrement spécifiée
R1(config)# ip route 192.168.3.0 255.255.255.0 s0/0/0 192.168.2.2

Le choix ici : la méthode 2 ou la 3. S0/0/0 est une liaison série, donc point à point : il n'y a qu'un seul voisin possible au bout du câble. Nommer l'interface suffit et évite au routeur toute recherche supplémentaire.

🧰 La règle de choix
Type de liaisonMéthodeRaison
Point à point (série)Interface de sortie Un seul voisin possible — pas d'ambiguïté
Multi-accès (Ethernet)Next-hop Plusieurs voisins partagent le lien : il faut désigner lequel

Utiliser l'interface de sortie seule sur un Ethernet fonctionne mais force le routeur à faire un ARP pour chaque destination, comme si tout le réseau distant était directement connecté. C'est inutilement coûteux.

3Routes précises ou route par défaut ? Moyen

Pour chaque routeur, dites s'il faut des routes précises ou une route par défaut, et écrivez-la.

  1. Le routeur d'une agence, relié uniquement au siège.
  2. Un routeur central relié à trois agences.
  3. La box d'un particulier.
  4. Un routeur d'agence relié au siège et à un accès Internet de secours.
✅ Correction
CasChoixPourquoi
1 — Agence, une seule sortieRoute par défaut C'est un réseau d'extrémité : tout part du même côté
2 — Routeur centralRoutes précises Trois directions différentes : il faut savoir laquelle pour chaque destination
3 — Box particulierRoute par défaut Une seule sortie vers l'opérateur. C'est l'exemple type
4 — Agence à double accèsLes deux Routes précises vers le siège, plus une route par défaut de secours avec une AD supérieure
Cisco IOS
! 1 et 3 — réseau d'extrémité
R-agence(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.1

! 2 — routeur central, trois directions
R-central(config)# ip route 192.168.10.0 255.255.255.0 10.0.0.2
R-central(config)# ip route 192.168.20.0 255.255.255.0 10.0.0.6
R-central(config)# ip route 192.168.30.0 255.255.255.0 10.0.0.10

! 4 — chemin principal + secours (route flottante)
R-agence(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.1          ← AD 1 par défaut
R-agence(config)# ip route 0.0.0.0 0.0.0.0 172.16.0.1 10     ← AD forcée à 10
🌍 La route flottante

Dans le cas 4, la seconde route porte une distance administrative de 10 au lieu de 1. Comme l'AD la plus faible gagne, elle reste invisible dans la table tant que la route principale fonctionne.

Si la liaison vers le siège tombe, la route principale disparaît de la table et la route de secours prend automatiquement sa place. C'est le seul moyen d'obtenir une forme de tolérance de panne en routage statique — et c'est exactement pour cela qu'on peut choisir l'AD manuellement.

03Lire une table de routage

4Décoder chaque ligne Moyen

R2# show ip route

     172.31.0.0/16 is variably subnetted, 5 subnets, 4 masks
C       172.31.0.0/24   is directly connected, GigabitEthernet0/0
L       172.31.0.1/32   is directly connected, GigabitEthernet0/0
S       172.31.1.0/25   [1/0] via 10.0.0.1
S       172.31.1.128/26 [1/0] via 10.0.0.5
     10.0.0.0/30 is subnetted, 2 subnets
C       10.0.0.0/30     is directly connected, Serial0/0/0
C       10.0.0.4/30     is directly connected, Serial0/0/1
S*   0.0.0.0/0 [1/0] via 192.0.2.1
  1. Combien de réseaux R2 connaît-il directement, et combien a-t-il appris ?
  2. Que signifient les [1/0] ?
  3. Que signifie l'astérisque de la dernière ligne ?
  4. Un paquet arrive pour 172.31.1.200. Quelle route est utilisée, et pourquoi ?
  5. Un paquet arrive pour 8.8.8.8. Que fait R2 ?
✅ Correction

1. Directement connectés / appris

Trois réseaux directement connectés (C) : 172.31.0.0/24, 10.0.0.0/30 et 10.0.0.4/30.

Trois routes apprises (S) : 172.31.1.0/25, 172.31.1.128/26 et la route par défaut.

La ligne L n'est pas un réseau : c'est l'adresse propre de l'interface, en /32.

2. [1/0]

1 = la distance administrative — celle d'une route statique.
0 = la métrique. Une route statique a toujours une métrique nulle : elle n'est pas calculée, elle est décidée.

3. L'astérisque

S* signale la route candidate par défaut — celle utilisée pour toute destination sans correspondance plus précise. C'est la gateway of last resort.

4. Le paquet pour 172.31.1.200

Trois routes pourraient correspondre. Il faut appliquer la correspondance la plus longue :

RoutePlage couverteContient .200 ?Bits
172.31.1.0/25.1.0 → .1.127Non25
172.31.1.128/26.1.128 → .1.191Non26
0.0.0.0/0toutOui0

Réponse : la route par défaut, via 192.0.2.1.

⚠️ Le vrai piège de cette question

On lit « 172.31.1.200 » et on saute sur 172.31.1.128/26 parce que les trois premiers octets correspondent. Mais un /26 à partir de .128 ne couvre que .128 à .191 — le pas est de 64. L'adresse .200 tombe dans le bloc suivant, qui n'est déclaré nulle part.

Il faut toujours calculer la plage réelle, jamais se fier à l'apparence des octets. C'est l'adressage IPv4 du chapitre 04 qui sert ici.

5. Le paquet pour 8.8.8.8

Aucune route précise ne correspond. R2 utilise la route par défaut et transmet le paquet à 192.0.2.1.

S'il n'y avait pas de route par défaut, le paquet serait abandonné et R2 renverrait un message ICMP Destination unreachable à l'émetteur.

04Exolab — trois services

5Routage statique sur trois réseaux Moyen

Une entreprise comporte trois services plus ou moins autonomes, un réseau logique par service. Les trois réseaux sont interconnectés par des routeurs Cisco 1941, chaque segment étant équipé d'un commutateur 2960.

Décrivez la démarche complète, de la mise en place à la validation, et indiquez les points sur lesquels l'auto-correction de l'activité va vous juger.

✅ Correction

La démarche, dans l'ordre

  1. Placer les équipements selon le schéma, en respectant l'emplacement géographique et les noms.
  2. Câbler en mode non automatique, pour choisir les interfaces de départ et d'arrivée conformément au schéma.
  3. Adresser : chaque LAN dans son propre sous-réseau, chaque liaison inter-routeurs dans un /30 dédié.
  4. Configurer les interfaces des routeurs : adresse, masque, no shutdown, et clock rate côté DCE.
  5. Vérifier la connectivité directe : chaque routeur doit pinguer son voisin immédiat. Ne pas aller plus loin tant que ce point n'est pas acquis.
  6. Écrire les routes statiques, dans les deux sens, sur chaque routeur.
  7. Configurer les postes : adresse, masque, et surtout passerelle par défaut.
  8. Tester de bout en bout par ping, puis tracert pour visualiser le chemin.
⚠️ Ce que l'auto-correction vérifie

L'énoncé est explicite : « le nom des équipements conditionne l'autocorrection de l'activité : respectez bien les minuscules, majuscules et traits d'union ».

Une configuration parfaite avec un routeur nommé R1 au lieu de r1 peut être comptée fausse. Recopiez les noms du schéma caractère par caractère, y compris la casse.

Même exigence pour les numéros d'interface : le câblage automatique de Packet Tracer choisit les ports tout seul, ce qui ne correspond pas au schéma. D'où la consigne d'utiliser les connexions non automatiques.

🧰 L'ordre de test qui fait gagner du temps
méthode
1. Depuis R1 : ping l'interface du VOISIN direct
   → échec ? le problème est physique ou d'adressage. Rien d'autre ne marchera.

2. Depuis R1 : ping une interface DISTANTE (2 sauts)
   → échec ? il manque une route. Regardez show ip route.

3. Depuis un PC : ping sa PROPRE passerelle
   → échec ? adressage du PC ou interface du routeur down.

4. Depuis un PC : ping un PC d'un autre réseau
   → échec alors que 1 à 3 fonctionnent ? c'est la route RETOUR qui manque.

5. tracert depuis le PC → montre EXACTEMENT où le paquet s'arrête.

Cette progression isole la panne en quelques minutes. Tester directement l'étape 4 sans les précédentes ne dit rien d'exploitable.

05Dépanner un routage

6Le TP de dépannage Exigeant

La topologie :

  • R1 connecte le LAN 1 (172.31.1.0/25) et relie R2 par S0/0/0 ;
  • R2 est le routeur central, connecté à R1 (S0/0/0), à R3 (S0/0/1) et au LAN 2 (172.31.0.0/24) ;
  • R3 connecte le serveur (172.31.1.128/26) et relie R2 par S0/0/1.

PC1 (sur R1) ne joint ni PC2 (sur R2) ni le serveur (sur R3).

  1. Que doit obligatoirement contenir la table de routage de chaque routeur ?
  2. PC1 ping maintenant PC2, mais toujours pas le serveur. Où chercher ?
  3. PC1 ping le serveur, mais le serveur ne répond pas à un ping venant de PC1 alors que la trace montre que le paquet arrive. Que se passe-t-il ?
✅ Correction

1. Ce que chaque routeur doit connaître

Chaque routeur connaît gratuitement ses réseaux directement connectés. Il faut lui apprendre tous les autres.

RouteurConnu (C)À apprendre
R1LAN 1, liaison R1–R2 LAN 2 · réseau du serveur · liaison R2–R3
R2LAN 2, les deux liaisons LAN 1 (via R1) · réseau du serveur (via R3)
R3Réseau serveur, liaison R2–R3 LAN 1 · LAN 2 · liaison R1–R2

Simplification : R1 et R3 sont des réseaux d'extrémité — une seule sortie chacun. Une route par défaut suffit :

Cisco IOS
R1(config)# ip route 0.0.0.0 0.0.0.0 s0/0/0
R3(config)# ip route 0.0.0.0 0.0.0.0 s0/0/1

! R2 est central : deux directions, donc des routes précises
R2(config)# ip route 172.31.1.0   255.255.255.128 s0/0/0     ← /25 vers R1
R2(config)# ip route 172.31.1.128 255.255.255.192 s0/0/1     ← /26 vers R3
⚠️ Les masques de cet énoncé sont piégeux

/25 = 255.255.255.128 et /26 = 255.255.255.192. On écrit 255.255.255.0 par réflexe, et la route ne correspond alors à rien de ce qui existe.

Autre subtilité : 172.31.1.0/25 et 172.31.1.128/26 commencent par les mêmes trois octets mais sont deux réseaux distincts. Le /25 couvre .0 à .127, le /26 couvre .128 à .191. Aucune route « 172.31.1.0/24 » ne pourrait les distinguer.

2. PC2 est joint, mais pas le serveur

PC1 → PC2 passe par R1 puis R2 : les routes R1→R2 et le retour R2→R1 existent donc.

Le problème est au-delà de R2 — sur le segment R2 ↔ R3. Trois pistes, dans cet ordre :

  1. La route de R2 vers le réseau du serveur est absente ou porte un mauvais masque → show ip route sur R2.
  2. La route retour de R3 vers le LAN 1 est absente → le paquet arrive au serveur mais la réponse se perd.
  3. L'interface S0/0/1 de R2 ou R3 est down → show ip interface brief.
Cisco IOS
R2# show ip route | include 172.31.1.128     ← la route existe-t-elle ?
R2# ping 172.31.1.129                        ← R2 joint-il l'interface de R3 ?
R3# show ip route                            ← R3 sait-il revenir vers 172.31.1.0/25 ?

3. Le paquet arrive mais rien ne revient

C'est le symptôme caractéristique d'une route retour manquante — ou d'un pare-feu sur le serveur.

Deux causes possibles, à distinguer :

CauseComment la reconnaître
Route retour absente sur R3 show ip route sur R3 : aucune entrée pour 172.31.1.0/25. Un ping lancé depuis le serveur vers PC1 échoue également
Pare-feu du serveur R3 a bien la route. Un ping depuis R3 vers le serveur fonctionne, mais depuis PC1 non
🧰 Le réflexe à acquérir

Un ping qui part sans revenir n'est jamais un problème d'aller. Le paquet a manifestement trouvé son chemin. Cherchez donc systématiquement du côté du retour : la machine distante sait-elle revenir chez l'émetteur ?

C'est pour cette raison qu'une route statique se configure toujours par paire. Configurer l'aller sans le retour donne l'illusion d'un travail fait à moitié — alors qu'il ne fonctionne pas du tout.

⚡ Les erreurs qui coûtent le plus de points

  • Oublier no shutdown sur les interfaces du routeur.
  • Oublier clock rate côté DCE d'une liaison série.
  • Oublier la route retour. Une route statique se configure par paire.
  • Se tromper de masque — /25 = .128, /26 = .192, /30 = .252.
  • Oublier la passerelle par défaut sur les postes.
  • Confondre AD et métrique dans [1/0].
