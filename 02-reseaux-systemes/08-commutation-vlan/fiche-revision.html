Commutation et VLAN — l'essentiel

Deux pages à imprimer (⌘P). Les commandes, les valeurs, les pièges.

01Commutation

Les 2 étapes

  1. APPRENDRE — adresse MAC source → ajoutée à la table avec son port. Délai remis à 5 min
  2. TRANSFÉRER — adresse MAC destination :
    • connue → le seul port
    • inconnue → inondation, sauf le port d'entrée

Table MAC = table CAM. Jamais de renvoi sur le port d'entrée.

Un VLAN, c'est…

1 VLAN = 1 domaine de diffusion
= 1 sous-réseau IP

6 avantages : domaines de diffusion plus petits · sécurité · efficacité IT · coûts · performances · gestion simplifiée

Sans équipement de couche 3, deux VLAN ne communiquent pas.

03Trunk, 802.1Q et inter-VLAN

L'étiquette 802.1Q

4 octets insérés dans la trame
TPID2 o · 0x8100
Priorité3 bits · CoS
CFI1 bit · Token Ring
VID12 bits → 4094 VLAN utilisables

Le FCS est recalculé 2 fois : à l'ajout et au retrait de l'étiquette.

Le VLAN natif

Tout est étiqueté sur un trunk
SAUF le VLAN natif

⚠️ Doit être identique des deux côtés — sinon le trafic change de VLAN en traversant le câble.

Message Cisco : %CDP-4-NATIVE_VLAN_MISMATCH

Le déplacer hors du VLAN 1 protège de l'attaque par double étiquetage.

Les 3 solutions inter-VLAN

Hérité1 interface physique par VLAN — ne passe pas à l'échelle
Router-on-a-stick1 trunk + sous-interfaces — petite à moyenne taille
Switch L3 (SVI)Le plus évolutif

Router-on-a-stick — la configuration complète

! ── SWITCH : le port vers le routeur ──
S1(config)# interface fa0/2
S1(config-if)# switchport mode trunk
S1(config-if)# switchport trunk native vlan 99
S1(config-if)# switchport trunk allowed vlan 10,20,99

! ── ROUTEUR : une sous-interface par VLAN ──
R1(config)# interface g0/0.10
R1(config-subif)# encapsulation dot1q 10
R1(config-subif)# ip address 172.17.10.1 255.255.255.0

R1(config)# interface g0/0.99
R1(config-subif)# encapsulation dot1q 99 native      ← ⚠ « native » pour le VLAN NATIF
R1(config-subif)# ip address 172.17.99.1 255.255.255.0

R1(config)# interface g0/0
R1(config-if)# no shutdown                           ← ⚠ SANS ÇA, RIEN NE MARCHE

Les 7 étapes : créer les VLAN → SVI de gestion → ports d'accès → ports trunk → sous-interfaces → activer l'interface physique → tester.

04Vérifier et dépanner

Les commandes show

show vlan brief              VLAN + ports ★
show interfaces trunk        trunks, natif, autorisés ★
show interfaces fa0/18 switchport
show ip interface brief
show ip route                sur le routeur
show mac address-table

La méthode en 3 questions

  1. Même VLAN → ping OK ?
    Non → couche 2 : port mal affecté, trunk absent, VLAN non autorisé, pare-feu
  2. VLAN différents → ping OK ?
    Non → couche 3 : sous-interface, no shutdown, passerelle sur les postes
  3. Gestion joignable ?
    Non → SVI sans no shutdown, ip default-gateway, ou VLAN natif

Les 6 oublis classiques

  1. switchport mode access
  2. no shutdown sur l'interface physique du routeur
  3. native sur la sous-interface du VLAN natif
  4. Passerelle par défaut sur les postes
  5. Réaffecter les ports avant de supprimer un VLAN
  6. delete vlan.dat pour une vraie remise à zéro

VLAN voix — un port, 2 VLAN

S1(config-if)# switchport mode access
S1(config-if)# switchport access vlan 20   ← PC
S1(config-if)# switchport voice vlan 150   ← tél.
S1(config-if)# mls qos trust cos

Le téléphone = switch à 3 ports. Voix étiquetée, données non étiquetées. CDP informe le téléphone.

⚡ Si vous ne reteniez que trois choses

  • Un VLAN = un domaine de diffusion = un sous-réseau IP. Tout découle de là.
  • Le trunk étiquette tout, sauf le VLAN natif. Et le natif doit être identique des deux côtés.
  • Deux VLAN ne se parlent jamais sans couche 3. Router-on-a-stick : une sous-interface par VLAN, et no shutdown sur le port physique.
