WSL Containers (wslc) — QCM

16 questions. Une seule bonne réponse par question, et l'explication s'affiche dès que vous avez répondu. Le cours · La fiche

0 / 16

1Qu'est-ce qu'il faut installer en plus de Windows pour utiliser wslc ?

C'est tout l'intérêt de l'outil : wslc.exe est un binaire intégré à WSL. Il faut seulement que WSL soit à jour — version 2.9.3 ou supérieure — ce que donne wsl --update.

2Quelle commande met WSL à jour et donne donc accès aux conteneurs ?

wsl --update, dans PowerShell, puis un redémarrage du PC. wsl --version permet de vérifier qu'on a bien atteint 2.9.3.

3D'où wslc télécharge-t-il l'image ubuntu:latest ?

Ce n'est pas un format concurrent : wslc va chercher dans les mêmes registres que Docker — Docker Hub, GitHub Container Registry, Azure Container Registry. Une image construite pour Docker tourne sous wslc.

4Que fait exactement l'option --rm de wslc run ?

--rm ne touche pas à l'image, qui reste en cache. Elle détruit le conteneur à sa sortie, ce qui évite d'accumuler des dizaines de conteneurs arrêtés au fil d'un TP.

5Dans wslc run -d --rm -p 8080:80 --name web nginx, que signifie 8080:80 ?

Le dehors est toujours à gauche. On tape localhost:8080 dans son navigateur, et nginx répond depuis son port 80 à l'intérieur. Inverser les deux est l'erreur la plus fréquente, et elle ne produit aucun message : la page ne répond pas, c'est tout.

6Quelle est la différence entre wslc run et wslc exec ?

run part d'une image et fabrique un conteneur neuf. exec entre dans un conteneur qui existe déjà. Faire un run en croyant entrer dans son serveur donne un second serveur vide — et on cherche longtemps ses fichiers.

7Comment voir les conteneurs arrêtés, et pas seulement ceux qui tournent ?

wslc container list ne montre que ce qui tourne ; --all ajoute les conteneurs arrêtés. C'est la même logique que docker ps -a.

8À quoi sert wslc events ?

C'est un journal en direct. Lancé dans une console pendant qu'on travaille dans une autre, il montre la séquence réelle d'un run --rm : création, connexion au réseau, démarrage, arrêt, déconnexion, destruction.

9Comment s'appelle, dans le tutoriel de Microsoft, le fichier qui décrit la construction d'une image ?

Microsoft le nomme Containerfile. Son contenu ne change pas : FROM, WORKDIR, COPY, RUN, EXPOSE, CMD — exactement la syntaxe du chapitre 18.

10Dans un Containerfile, quelle est la différence entre RUN et CMD ?

RUN tourne une fois, pendant le build, et son résultat est figé dans l'image. CMD ne tourne pas du tout au build : c'est ce que fera le conteneur au démarrage. Mettre son serveur dans un RUN produit une image qui ne lance rien.

11Que vaut wslc build -t monimage . ?

Le point final est le contexte : le dossier qui contient le Containerfile et les fichiers à copier. -t donne le nom par lequel on pourra ensuite faire wslc run monimage.

12Pourquoi Microsoft recommande-t-il de garder les fichiers du projet du côté Linux (\\wsl$) ?

Les deux mondes se voient, mais chaque accès traverse une passerelle. Un build lit des milliers de fichiers : le même projet rangé côté Windows se construit nettement plus lentement.

13Qu'est-ce qui reste indispensable sur le PC pour que wslc fonctionne ?

WSL 2 fait tourner un vrai noyau Linux dans une machine virtuelle légère. Sans la virtualisation matérielle, WSL ne démarre pas — et wslc non plus. C'est le blocage classique en salle de TP, et il se règle dans le BIOS, pas dans Windows.

14Laquelle de ces affirmations est FAUSSE ?

wslc est un composant de Windows. Il fait tourner des conteneurs Linux, mais depuis Windows seulement. Sur un Mac ou un serveur Linux, c'est Docker ou Podman.

15Deux commandes font le ménage. Lesquelles ?

wslc container prune efface les conteneurs arrêtés, wslc image prune les images que plus aucun conteneur n'emploie. Ce sont les images qui pèsent : une dizaine d'essais occupent déjà un gigaoctet.

16Un Containerfile contient EXPOSE 8000. Le conteneur est lancé sans option -p. L'application est-elle joignable depuis Windows ?

EXPOSE est une indication écrite dans l'image : elle dit à qui la lit quel port l'application utilise. Elle n'ouvre rien. Seul -p 8000:8000, au lancement, crée réellement le passage entre la machine et le conteneur. C'est une des confusions les plus fréquentes, et elle ne produit aucun message d'erreur — la page ne répond pas, c'est tout.
