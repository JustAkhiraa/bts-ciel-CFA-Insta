⚡ Un trunk se configure par paire

La même liste allowed et le même VLAN natif aux deux extrémités — VLAN natif inclus dans la liste.

Un VLAN autorisé d'un seul côté est élagué : il se comporte comme un VLAN interdit, sans le moindre message d'erreur.

⚡ ip helper-address

Un routeur bloque les broadcasts. Le DHCPDISCOVER d'un poste sans adresse part vers 255.255.255.255 et meurt sur la sous-interface.

Cisco IOS
interface g0/0.10
 ip helper-address 192.168.20.11
interface g0/0.30
 ip helper-address 192.168.20.11
!  g0/0.20 : RIEN — le serveur y est déjà

Le relais fait deux choses : broadcast → unicast, et il inscrit l'adresse de la sous-interface dans le champ giaddr — c'est lui qui dit au serveur dans quel pool puiser.

⚡ ACL — l'ordre est la règle

Cisco IOS
ip access-list extended PROTECT_ADMIN
 permit ip 192.168.10.0 0.0.0.255 host 192.168.20.10
 permit ip 192.168.10.0 0.0.0.255 host 192.168.20.11
 deny   ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
 permit ip any any

interface g0/0.20
 ip access-group PROTECT_ADMIN out

Lue de haut en bas, s'arrête à la première correspondance. Exceptions (host) d'abord, refus large ensuite.

Le permit ip any any final contre le deny implicite — sans lui, tout est bloqué.

⚡ Check-list « nouveau VLAN »

  1. créer le VLAN sur chaque switch traversé
  2. affecter les ports d'accès
  3. l'ajouter aux listes allowed de tous les trunks — l'oubli n° 1
  4. sous-interface routeur : encapsulation dot1q + IP
  5. reporter ip helper-address, ip nat inside, ACL
  6. créer le pool DHCP

Trunk oublié = les postes se voient entre eux mais ne sortent pas du switch.

⚡ Les pièges vus sur ce projet

  • no ip dhcp excluded-address — le no supprime l'exclusion : le pool peut distribuer la passerelle
  • dns-server pointant vers une machine inexistante — les pings par IP passent, les noms non
  • VLAN 99 absent de la liste allowed d'un côté du trunk
  • VLAN 999 annoncé dans le rapport, jamais créé sur le switch
  • rapport décrivant une version antérieure à la maquette livrée

L'oral — quoi · pourquoi · limite

QuestionLe cœur de la réponse
VLAN plutôt que réseaux physiques ? même isolation, un seul matériel, réaffectation par commande. Limite : dépend de la configuration.
VLAN natif en 99 ? le natif circule sans étiquette ; en VLAN 1 il ouvre au VLAN hopping.
ip helper-address ? un routeur bloque les broadcasts ; le relais convertit et renseigne giaddr.
Deux types de routes ? stub → défaut ; nœud à plusieurs sorties → précises.
Statique plutôt que PAT ? le besoin est entrant. Limite : aucun poste ne sort — il faudrait PAT + route par défaut.
Votre faiblesse ? SW-COEUR est un SPOF → EtherChannel + HSRP. Lien unique vers l'entrepôt, non chiffré.

C'est la troisième colonne — la limite — qui fait la différence. Savoir où une solution cesse de convenir prouve qu'on l'a choisie.
