EtherChannel : le TP

Trois commutateurs, trois agrégats : un en PAgP, deux en LACP. Chaque étape se termine par une vérification à l'écran. Les commandes se copient d'un clic ; coche les actions au fur et à mesure. Les six questions du TP sont posées à leur place, réponse repliable. Le cours · Les exercices

🎯 Avant de commencer

Il faut trois commutateurs Cisco 2960, trois PC, les câbles console et les câbles Ethernet de la topologie.

Le TP se fait aussi bien sur du matériel réel que dans un simulateur.

Chaque bloc de commandes est coloré selon le commutateur où il faut le taper :
bleu pour S1, vert pour S2, rouge pour S3, gris pour ce que l'écran répond.

🔧 Corrigé : des commutateurs, pas des routeurs

L'énoncé parle de « routeurs Cisco Catalyst 2960 ».

Le Catalyst 2960 est un commutateur. Ce TP ne contient d'ailleurs aucun routage, bien que son introduction en annonce :
les trois PC sont dans le même réseau.

01La configuration de base

Rien d'EtherChannel ici : on prépare le terrain. Noms, mots de passe, VLAN, adresses. Un seul point demande de l'attention, à l'étape 1.4.

1.1 · Câbler

Les voyants des ports entre commutateurs peuvent rester éteints ou orange. C'est normal :
on va les éteindre exprès à l'étape 1.4.

1.2 · Repartir de zéro

Cisco IOS · S1, puis S2 et S3
enable
erase startup-config
delete vlan.dat
reload

Répondre Entrée à la demande de nom de fichier, confirmer l'effacement, et refuser la sauvegarde proposée avant le redémarrage.

💡 Pourquoi effacer aussi vlan.dat

Les VLAN ne sont pas rangés dans la configuration de démarrage, mais dans un fichier à part. erase startup-config seul laisse donc les anciens VLAN en place.

1.3 · Les réglages de base de S1

Cisco IOS · S1
enable
configure terminal
no ip domain-lookup
hostname S1
service password-encryption
enable secret class
banner motd #Acces interdit#
line console 0
 password cisco
 login
 logging synchronous

line vty 0 15
 password cisco
 login
 logging synchronous
 exit
🧰 Ce que fait chaque ligne
  • no ip domain-lookup :
    une commande mal tapée n'est plus prise pour un nom de machine à chercher.
  • service password-encryption :
    les mots de passe ne restent pas en clair dans la configuration.
  • enable secret class :
    le mot de passe du mode privilégié, stocké chiffré.
  • logging synchronous :
    les messages du système ne coupent plus la commande en cours de frappe. Utile ici, un agrégat en produit beaucoup.

1.4 · Éteindre tous les ports, sauf celui du PC

Cisco IOS · S1
interface range f0/1-24, g0/1-2
 shutdown
 exit
interface f0/6
 no shutdown
 exit

Sur S2 et S3, le port du PC est f0/18.

⚠️ L'étape qui protège tout le reste

Tant que les ports sont éteints, aucune boucle ne peut se former pendant qu'on configure.

On ne les rallume qu'une fois le mode d'agrégation réglé des deux côtés. C'est la consigne du TP :
activer les ports après avoir configuré les modes.

02PAgP entre S1 et S3 : Po1

Premier agrégat. Un côté propose (desirable), l'autre accepte (auto).

2.1 · Déclarer l'agrégat

Cisco IOS · S1
configure terminal
interface range f0/3-4
 channel-group 1 mode desirable
 no shutdown
 end
Cisco IOS · S3
configure terminal
interface range f0/3-4
 channel-group 1 mode auto
 no shutdown
 end

Dès le channel-group, le commutateur annonce la création de l'interface logique. Puis, quelques secondes après le no shutdown, la console déroule :

sortie sur S3 · lignes repliées
Creating a port-channel interface
Port-channel 1

%LINK-3-UPDOWN:
  Interface FastEthernet0/3,
  changed state to up
%LINK-3-UPDOWN:
  Interface FastEthernet0/4,
  changed state to up
%LINK-3-UPDOWN:
  Interface Port-channel1,
  changed state to up
%LINEPROTO-5-UPDOWN:
  Line protocol on Interface
  Port-channel1, changed state to up

D'abord les deux ports physiques, puis Port-channel1. L'ordre raconte ce qui se passe :
les liens montent, se reconnaissent, et l'agrégat se forme par-dessus.

Les deux commutateurs doivent afficher la même dernière ligne.

Question · Que signifient les indicateurs SU et P ?

Dans le récapitulatif, que signifient SU et P ?

✅ Réponse

SU se lit sur le Port-channel, en deux lettres.

  • S, Layer2 :
    l'agrégat travaille au niveau 2, il commute.
  • U, in use : il est en service.

P se lit sur chaque port physique :
bundled in port-channel, le port est bien regroupé dans l'agrégat.

Pour le compte rendu :
« SU indique que le canal de port est un agrégat de niveau 2 en service ; P indique que le port physique en est membre. »

2.4 · Po1 en trunk, VLAN natif 99

Cisco IOS · S1
configure terminal
interface port-channel 1
 switchport mode trunk
 switchport trunk native vlan 99
 end
Cisco IOS · S3
configure terminal
interface port-channel 1
 switchport mode trunk
 switchport trunk native vlan 99
 end
💡 Le réflexe central du TP

Une fois les ports agrégés, les commandes se tapent sur le Port-channel. Elles s'appliquent toutes seules aux liens regroupés.

Le VLAN natif est le seul qui circule sans étiquette sur un trunk. Il doit être le même des deux côtés.

2.5 · Vérifier le trunk

Cisco IOS · S1, puis S3
show run interface f0/3
show run interface f0/4
show run interface port-channel 1

Question · Quelles commandes pour F0/3 et F0/4 ?

Quelles commandes sont listées pour F0/3 et F0/4 sur les deux commutateurs ? Comparer avec la configuration de Po1.

✅ Réponse

Les deux ports affichent désormais les mêmes lignes que Po1, plus la leur :

sortie
interface FastEthernet0/3
 switchport trunk native vlan 99
 switchport mode trunk
 channel-group 1 mode desirable

Sur S3, la dernière ligne se termine par auto.

Observation. Les commandes tapées sur Port-channel 1 ont été recopiées automatiquement sur ses ports membres. La seule différence est la ligne channel-group, qui n'existe que sur les ports physiques :
c'est elle qui les rattache à l'agrégat.

Cisco IOS · S1, puis S3
show interfaces trunk
show spanning-tree

Question · Quel port trunk, quel VLAN natif ?

Quel est le port trunk répertorié ? Quel est le VLAN natif ? Qu'en conclure ?

✅ Réponse

Le port trunk répertorié est Po1, et lui seul. Ni Fa0/3 ni Fa0/4 n'apparaissent.

Le VLAN natif est le 99.

Conclusion. Pour la commutation, les deux liens physiques n'existent plus séparément. Ils sont remplacés par une seule interface logique, et c'est ce qui empêche le spanning-tree de bloquer l'un des deux câbles.

Question · Coût et priorité du lien agrégé

Dans show spanning-tree, quels sont le coût du port et la priorité du port de la liaison agrégée ?

✅ Réponse

Le coût est 12. Un lien FastEthernet seul coûte 19 :
agrégés, deux liens coûtent moins, parce que la bande passante a augmenté.

La priorité est 128, la valeur par défaut d'un port. Elle se lit dans la colonne Prio.Nbr, devant le point.

Le nombre placé après le point dépend du matériel :
note celui que ton écran affiche.

03LACP : Po2 et Po3

💡 L'ordre change, exprès

En partie 2, on a agrégé d'abord, puis mis le Port-channel en trunk.

Ici, les ports physiques sont mis en trunk avant d'être regroupés. Les deux ordres fonctionnent, tant que les ports sont identiques au moment de l'agrégation.

3.1 · Po2, entre S1 et S2

Cisco IOS · S1
configure terminal
interface range f0/1-2
 switchport mode trunk
 switchport trunk native vlan 99
 channel-group 2 mode active
 no shutdown
 end
Cisco IOS · S2
configure terminal
interface range f0/1-2
 switchport mode trunk
 switchport trunk native vlan 99
 channel-group 2 mode passive
 no shutdown
 end

3.2 · Vérifier Po2

Cisco IOS · S1, puis S2
show etherchannel summary
sortie sur S1 · colonnes repliées
Group  Port-channel  Protocol
       Ports
------+-------------+---------
1      Po1(SU)       PAgP
       Fa0/3(P)  Fa0/4(P)
2      Po2(SU)       LACP
       Fa0/1(P)  Fa0/2(P)

Deux agrégats, deux protocoles, sur le même commutateur. C'est permis :
le protocole doit être le même aux deux bouts d'une liaison, pas sur tout le commutateur.

Question · Le protocole de Po2

Quel protocole utilise Po2 ? Quels ports sont agrégés pour le former ? Quelle commande a servi à le vérifier ?

✅ Réponse

Po2 utilise LACP.

Il regroupe Fa0/1 et Fa0/2, sur S1 comme sur S2.

La commande est show etherchannel summary.

show lacp neighbor la complète :
elle prouve que le voisin négocie bien.

3.3 · Po3, entre S2 et S3

⚠️ Les numéros de ports ne sont plus les mêmes

Côté S2, ce sont F0/3-4. Côté S3, ce sont F0/1-2.

Cisco IOS · S3

04Vérifier de bout en bout

invite de commandes · PC-A
ping 192.168.10.2
ping 192.168.10.3
Cisco IOS · S1
ping 192.168.99.12
ping 192.168.99.13

Le premier test traverse les agrégats dans le VLAN 10. Le second valide en plus le trunk et le VLAN natif 99.

⚠️ Un ping qui échoue n'accuse pas toujours le commutateur

Le tout premier ping échoue parfois :
relance-le avant de conclure.

Sur de vraies machines, le pare-feu du PC peut aussi bloquer la réponse.

Cisco IOS · S1, puis S2 et S3
show spanning-tree vlan 10

Un des trois Port-channel apparaît bloqué sur l'un des commutateurs. C'est normal :
les trois forment un triangle, donc une boucle, et le spanning-tree en coupe un côté.

En plus : voir la redondance

invite de commandes · PC-A
ping -t 192.168.10.2

Le ping continue. Le récapitulatif montre alors un port en (P) et l'autre en (D) :
l'agrégat tourne sur un seul câble. Rebranché, le port repasse en (P) sans aucune commande.

05La question de bilan

Question · Qu'est-ce qui pourrait empêcher la formation des EtherChannel ?

Lister ce qui peut empêcher un EtherChannel de se former.

✅ Réponse

1. Des modes incompatibles.

Un côtéL'autre côtéRésultat
desirabledesirable ou auto✅ l'agrégat monte, en PAgP
autoauto❌ personne ne propose
activeactive ou passive✅ l'agrégat monte, en LACP
passivepassive❌ personne ne propose
onon✅ l'agrégat monte, sans négociation
desirable ou autoactive ou passive❌ deux protocoles différents
ontout autre mode❌ un côté négocie, l'autre non

2. Des réglages qui diffèrent entre les ports ou entre les deux côtés :

  • des interfaces qui ne prennent pas en charge EtherChannel ;
  • une vitesse ou un duplex différents ;
  • un côté en accès, l'autre en trunk ;
  • une plage de VLAN autorisés ou un VLAN natif différents.

3. Des erreurs de mise en œuvre :

  • des ports restés en shutdown ;
  • un channel-group oublié d'un côté ;
  • une configuration faite sur un seul port physique au lieu du Port-channel.

💡 Le geste à retenir

Après chaque modification, une seule commande fait foi :
