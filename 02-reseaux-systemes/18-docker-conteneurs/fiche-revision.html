« L'image est le modèle, le conteneur est l'exécution, le volume est la mémoire. »

Conteneur ou VM

Une VM embarque un système entier et son noyau : plusieurs Go, dizaines de secondes.

Un conteneur partage le noyau de l'hôte : quelques dizaines de Mo, moins d'une seconde.

VM Debian installée : plusieurs Go · image debian : une centaine de Mo · image alpine : moins de 10.

⚡ Les deux lectures

bash
-p 8080:80                       hote : conteneur
-v donnees:/usr/share/nginx/html  volume : point de montage

Le dehors est toujours à gauche. C'est la seule chose à retenir, et elle évite les deux erreurs les plus fréquentes du TP.

Les images

bash
docker pull nginx          telecharger
docker pull nginx:1.21     une version precise
docker images              lister
docker rmi nginx:1.21      supprimer

Le tag fait partie de l'identité. nginx et nginx:1.21 sont deux images, deux IMAGE ID.

latest = « par défaut », pas « la plus récente ».

Les conteneurs

bash
docker run -it alpine sh            interactif
docker run -d --name web nginx      detache, nomme
docker ps        /  docker ps -a    actifs / TOUS
docker logs web  /  docker logs -f
docker exec -it web bash            entrer DANS
docker stop / start / restart web
docker rm web    /  docker rm -f web

run crée, exec entre.

Un conteneur vit tant que son processus principal vit.

Alpine n'a pas bash, seulement sh.

Les volumes

bash
docker volume create donnees-web
docker run -d -p 8082:80 \
  -v donnees-web:/usr/share/nginx/html nginx
docker volume ls / inspect / rm

Le volume survit à docker rm. C'est la seule façon de garder des données.

Monté sur un dossier non vide, il le masque entièrement — sauf au tout premier montage, où son contenu y est recopié.

Nettoyer

bash
docker system df            ce que ca occupe
docker container prune      conteneurs arretes
docker image prune -a       images inutilisees
docker volume prune         volumes orphelins
docker system prune         les trois

docker system prune -a --volumes efface aussi les données. Regarder df d'abord.

⚡ Les pièges du TP

  • docker ps cache les conteneurs arrêtés.
  • run au lieu de exec → on modifie un autre conteneur.
  • bash n'existe pas dans Alpine.
  • stop/start garde les modifications, rm les efface.
  • Deux conteneurs peuvent écouter le port 80 : seul le port de l'hôte doit être unique.
  • rm refuse un conteneur actif ; rmi refuse une image utilisée ; volume rm refuse un volume monté.
  • $(docker ps -q) échoue si la liste est vide.

Installer, en une ligne par système

macOS · Windows — Docker Desktop. Sous Windows, wsl --install d'abord, et la virtualisation activée dans le BIOS.

Linux — le dépôt officiel, jamais apt install docker.io. Puis sudo usermod -aG docker $USER, et rouvrir la session.

Vérifier — docker info, pas docker --version : seul le premier prouve que le moteur répond.

Le groupe docker équivaut à root.
